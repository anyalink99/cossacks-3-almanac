# Правила читательской документации

[English](../../internals_en/project/documentation_style.md) · **Русский**

[← Устройство и сопровождение проекта](README.md)

Эти правила обязательны для `docs/**/*.md`, шаблонов в
`writers/templates/`, читательских фрагментов в `internals/**/*.md` и их
английских зеркал. Цель — объяснять игру обычному читателю, не теряя точности,
необходимой для проверки по скриптам.

## 1. Сначала игровое понятие, затем внутренний идентификатор

В основном тексте всегда используется каноническое название из локализации
игры. Внутренний код, SID, имя поля или функции приводится только после него
и оформляется как `code`.

| Плохо | Хорошо |
|---|---|
| объект `eurtow` | **Башня** (`eurtow`) |
| `gainres` — приказ крестьянину | приказ «добывать ресурс» (`gainres`) |
| юнит с `priest` лечит цель | **Капеллан** (`priest`) лечит союзника |
| параметр `capture` | правила захвата объектов (`capture`) |

В таблицах каноническое название ставится в первый столбец. Если внутренний
код нужен читателю, для него создаётся отдельный столбец «Внутренний код» или
он указывается после названия: **Башня** (`eurtow`).

Источники канонических названий:

- [`derived/canonical_terms.json`](../../derived/canonical_terms.json);
- функции и словари в [`parser/config.py`](../../parser/config.py);
- русская и английская локали игры, из которых собирается словарь.

Если названия в словаре нет, сначала исправляется источник словаря. Нельзя
придумывать отдельное соответствие внутри статьи или генератора.

## 2. Русский читательский текст не смешивается с жаргоном движка

Если у термина есть обычный русский эквивалент, используется он:

| Не использовать в прозе | Использовать |
|---|---|
| `build order` | порядок строительства |
| `attack-move` | атака с движением |
| `handler`, `callback` | обработчик |
| `queue` | очередь |
| `target`, `owner` | цель, владелец |
| `spawn` | создание или появление |
| `range`, `damage`, `pause` | дальность, урон, перезарядка |
| `HP`, `max HP` | здоровье, максимальное здоровье |
| `DPS` | урон в секунду |
| `UI`, `FOW` | интерфейс, туман войны |
| `state machine` | автомат состояний |

Точное имя поля или команды сохраняется как техническая справка:
«максимальное здоровье (`maxhp`)», «обработчик `_unit_OnDeath`».

Нельзя образовывать русские слова от английского идентификатора:
`sid'ы`, `handler'ы`, `capture-логика`. Следует писать «внутренние
идентификаторы», «обработчики», «логика захвата».

Латиница вне `code` допустима только для собственных названий и общеупотребимых
обозначений, которые нельзя перевести без искажения: Cossacks 3, Pascal,
Windows, Age of Empires II, XVII–XVIII века.

## 3. Читательский и технический слои разделяются

Статья в `docs/` начинается с того, что видит игрок:

1. краткий ответ или практический вывод;
2. понятное описание механики;
3. формулы и числовые примеры;
4. внутренние поля, функции и подтверждающие фрагменты;
5. источники и открытые вопросы.

Нельзя начинать статью с перечня функций, SID или незакрытых задач. Если
материал интересен только разработчику или моддеру, ему место в `internals/`,
а из читательской статьи достаточно дать ссылку.

Внутренний термин можно вынести в заголовок только вместе с человеческим
названием: «Время мира (`peacetime`)», а не «`peacetime`».

## 4. Факт, вывод и гипотеза не смешиваются

- Подтверждённое скриптом или данными описывается как факт и получает ссылку
  на источник.
- Вывод из нескольких источников явно помечается как вывод.
- Непроверенное поведение помечается как гипотеза или открытый вопрос.
- Если функция, автомат состояний или загрузчик не найден, нельзя заявлять,
  что он существует.

Точные имена, значения и фрагменты кода нельзя «улучшать» ради красивого
текста. Переводится объяснение вокруг них, а литерал остаётся неизменным в
`code` или настоящем кодовом блоке.

## 5. Кодовые блоки используются только по назначению

В fenced-блоках оставляются:

- настоящий код или псевдокод;
- буквальные данные игры;
- диаграммы Mermaid;
- схемы, где моноширинное расположение имеет смысл.

Обычная проза, таблицы и авторские пояснения не должны прятаться в блоке кода.
В английской версии авторские подписи, комментарии и схемы переводятся.
Настоящие идентификаторы и буквальные данные игры не переводятся.

Если изменён авторский fenced-блок, после проверки обеих языковых версий
обновляется каталог ручных переводов:

```bash
python scripts/build_english_docs.py --capture-fenced-translations
```

## 6. Английское зеркало обновляется вместе с русской статьёй

Для каждого файла в `docs/` и `internals/` должно существовать зеркало в
`docs_en/` или `internals_en/`.

- Используются канонические английские названия из
  `canonical_terms.json`.
- Реальные SID, поля, функции и значения остаются неизменными.
- Перевод передаёт смысл, а не копирует русский порядок слов.
- Новые русские заголовки добавляются в английский файл как совместимые
  `<a id="..."></a>` перед соответствующим английским заголовком.
- Старый якорь сохраняется как дополнительный alias, если адрес уже мог
  использоваться во внешних ссылках.
- Число заголовков, таблиц, сносок и fenced-блоков в паре не должно
  расходиться без осознанной причины.

## 7. Markdown и навигация

- Заголовок пишется с пробелом после `#`.
- Явные `id` уникальны внутри страницы.
- Текст ссылки объясняет назначение страницы; подписи `Index` и голые имена
  файлов не используются в читательской навигации.
- Внутристраничная ссылка проверяется в браузере, особенно после переименования
  заголовка.
- Для `docs/recon/` сохраняется ссылка «Как устроена игра», для технических
  статей — ссылка на соответствующий индекс `internals/`.

## 8. Проверки перед коммитом

После ручного изменения русской статьи и английского зеркала:

```bash
# Если менялись авторские fenced-блоки:
python scripts/build_english_docs.py --capture-fenced-translations

# Подтвердить проверенную пару и обновить поиск:
python scripts/build_english_docs.py --adopt-existing
python compute/build_md_manifest.py

# Обязательные проверки:
python scripts/build_english_docs.py --check
python scripts/check_markdown_links.py
python -m unittest discover -s tests -v
git diff --check
```

Тесты в
[`tests/test_reader_facing_docs.py`](../../tests/test_reader_facing_docs.py)
дополнительно запрещают в русской прозе `docs/recon/` голые объектные SID,
неоформленную латиницу и известный жаргон движка.
