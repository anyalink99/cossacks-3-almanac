# Empirical tests — что нужно проверить в игре

Открытые вопросы, которые нельзя закрыть только чтением кода. Пользователь запускает игру и проводит замеры; результаты возвращаются в `recon/peasant_extraction.md` § Constants.

**Контекст для всех тестов**: game speed = **normal (1×)** для чистого замера, потом конвертируется в наши формулы через множитель ×1.4 для fast.

---

## Test 1 — Скорость крестьянина (приоритет 🔴 P1)

**Цель:** определить `V_g` — тайлов в игр-секунду для крестьянина.

**Подготовка:**
1. Загрузить миссию или скирмиш на любой карте. Game speed = **normal**.
2. Поставить 2 склада (sto/cen — любые, главное чтобы было видно). Расстояние между ними — например, ширина экрана (~30-40 тайлов, на глаз).
3. Открыть редактор/F6 если возможно — там часто видна сетка с координатами. Если нет — просто ориентироваться на размеры зданий.

**Замер:**
1. Поставить крестьянина точно у resourcePoint первого склада (там, где приходит вернуть ресурс).
2. По правому клику отдать команду перейти ко второму складу (точка resourcePoint).
3. Засечь секундомером **время с момента команды до момента касания resourcePoint** второго склада.
4. Повторить 3-5 раз, усреднить.

**Калибровка расстояния:**
- Если в игре нет прямого индикатора, использовать здания как линейку. Town center (`*cen`) в `unit.script:2370` имеет `aabbmin/max` — обычно ~6×6 тайлов.
- ИЛИ: поставить 5 жилищ (`*hou`) в линию вплотную. Каждый ~4 тайла → 5 домов = 20 тайлов.

**Расчёт:**
```
V_g (tiles per game-sec) = distance_tiles / time_seconds
```
(При normal speed game-sec = real-sec.)

**Ожидание для здравой санити:**
- Если V_g ≈ 0.75 → peasant очень медленный (1 тайл за 1.3 g-sec). Маловероятно.
- Если V_g ≈ 2-3 → нормальный диапазон (тайл за 0.3-0.5 g-sec).
- Если V_g ≈ 24 → ОЧЕНЬ быстрый (если speed=40 интерпретируется как пикс/кадр). Проверить.

**Куда записать:** `recon/peasant_extraction.md` §3 "Скорости" — заменить `⚠ нужен empirical test` на найденное значение, и обновить `extraction_formulas.md` §6.

## Test 2 — FPS work-анимации (приоритет 🔴 P2)

**Цель:** проверить допущение "1 кадр = 1/32 g-sec" для анимаций добычи.

**Замер:**
1. Game speed = **normal**. Любая нация.
2. Поставить крестьянина рубить **гигантское** дерево (HP > 1000 — будет рубить долго). Признак гиганта — обычно высокое и толстое визуально.
3. Засечь время **10 полных взмахов топора** (10 циклов "вверх-вниз").

**Расчёт:**
```
T_workwood_actual = total_time / 10
```
**Ожидание:** T_workwood ≈ 0.5625 g-sec (= 18 frames / 32 fps). Если значение существенно другое (например, 1.0 или 0.3), значит FPS анимации не равен 32.

**Альтернативное замерение через сдачу:**
1. Поставить крестьянина рубить дерево, склад вплотную (≤1 тайл).
2. Дождаться **первой сдачи** (28 wood пришли в банк). Засечь от первого удара.
3. Это 14 циклов + ~0 walking → `T_workwood × 14 = total`.
4. `T_workwood = total / 14`.

**Куда записать:** `recon/peasant_extraction.md` §3 "Анимация — кадры одного work-цикла" таблица — добавить столбец empirical-measured. Если совпадает с теоретическими — снять ⚠.

## Test 3 — Подтверждение предпочтения деревьев (приоритет 🟡 P3)

**Цель:** проверить, что предпочтение целых деревьев работает только когда на пне уже кто-то рубит.

**Сценарий A — пустой пень vs целое дерево:**
1. На карте найти 2 близко стоящих дерева (≤2 тайла друг от друга), оба явно небольшие.
2. Один крестьянин рубит первое до пенька (HP=0, мешка стала пнём). Уведите его сдавать wood (или просто отозвать).
3. Поставить нового крестьянина в точку между двумя ресурсами.
4. Дать ему команду рубить → автопоиск выберет ближайший.

**Ожидание из формулы:** ближний победит независимо от типа (пень или дерево), если оба = 0 рубщиков. То есть наш найденный механизм "preference" НЕ работает на пустом пне.

**Сценарий B — занятый пень vs целое дерево:**
1. Тот же setup, 2 рядом стоящих дерева.
2. Крестьянин 1 рубит первое до пенька, остаётся рубить дальше (HP уходит в минус, но он продолжает).
3. Ставим крестьянина 2 чуть в стороне, даём команду на этот же район (правый клик в forest).
4. Должен пройти к **целому дереву**, проигнорировав пень с рубщиком.

**Ожидание из формулы:** ×3.5 penalty за рубщика → крестьянин 2 идёт к незанятому дереву даже если оно дальше.

**Сценарий C — расстояние "форы":**
1. Целое дерево в N тайлах, пень с 1 рубщиком в 2 тайлах.
2. Подбирать N: при N=4-5 крестьянин ещё идёт к целому, при N≈8 (на пределе search radius=6) выбор может смениться.

**Куда записать:** `recon/peasant_extraction.md` §4.2 — добавить блок "Эмпирическое подтверждение предпочтения".

## Test 4 — Влияние fast-speed на тайминги (приоритет 🟢 P4)

**Цель:** убедиться, что fast = ровно ×1.4 (не другое), и что все наши тайминги корректно скейлятся.

**Замер:**
1. Game speed = **fast**.
2. Тот же тест 1 (расстояние между складами): время будет меньше.
3. Сравнить `time_normal / time_fast` — должно быть ≈ 1.4.

**Куда записать:** `recon/peasant_extraction.md` §1 — добавить confirmation.

## Test 5 — Время сдачи на складе (приоритет 🟢 P5)

**Цель:** проверить что нет дополнительной задержки на сдачу (в кадрах).

**Замер:**
1. Game speed = normal. Склад прямо у дерева.
2. Засечь интервал между **последним 14-м ударом** и **появлением 28 wood в счётчике**.

**Ожидание:** ≈0 (мгновенно), может быть 1-2 кадра задержки. Если больше — это walk_within_drop_radius (radius 0.71 тайла, peasant тратит секунду чтобы дойти).

## Test 6 — Field regen rate (приоритет 🟢 P6)

**Цель:** подтвердить что регенерация полей работает как мы поняли.

**Замер:**
1. Поставить мельницу с уже растущим полем.
2. Выкачать поле до HP ≈ 14000 (visual stage_0 ещё, но уже не max). Это потребует ~110 ударов одним крестьянином.
3. Отвести крестьянина. Засечь время.
4. Через 100 g-sec посмотреть HP поля (через UI tooltip если показывается).

**Ожидание:** за 100 g-sec пройдёт ~3 регенерации (каждые 31.25 g-sec) → +3 × random(0..2500) ≈ +3750 в среднем → HP ≈ 17750.

**Если HP отображается через UI** — возможно увидим количество "урожаев" или %.

## Что записать после каждого теста

В `recon/peasant_extraction.md` при каждом подтверждённом значении:
1. Заменить ⚠/допущения на реальные числа.
2. Указать дату теста и нацию (например, "**Tested 2026-04-28 with peaaus, normal speed:** workwood = 0.563 ± 0.02 sec").
3. Если расхождение с теорией — открыть новый вопрос в §9 "Открытые вопросы".

В `recon/extraction_formulas.md` пересчитать таблицы с подтверждёнными константами и убрать "⚠" пометки в §6.
