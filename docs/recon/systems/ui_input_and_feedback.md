# Управление и обратная связь

[← Как устроена игра](../README.md)

Как работают выделение, камера, горячие клавиши, звук и предупреждения.
Основные разделы описывают результат для игрока; точные функции движка
приведены в технических таблицах и источниках.

> **Связанные документы:**
> [Обзор и туман войны](../world/combat/vision_and_fow.md)
> — туман войны и обзор; [Приказы юнитам](../world/combat/unit_commands.md)
> — какие приказы юнит понимает.

## Кратко

- Одиночный щелчок выбирает объект под курсором; рамка обновляет набор
  выбранных объектов, пока кнопка мыши удерживается.
- **Звуки и туман войны — две независимые системы.** Звук определяется
  расстоянием от точки прослушивания (камеры или объекта), а **не
  видимостью**.
  Юнит во вражеском «тумане» **слышен**, если попадает в радиус
  слышимости камеры.
- **Предупреждения** («вас атакуют», «захватывают») срабатывают
  только если событие происходит **вне поля зрения камеры** (то
  есть игрок физически не смотрит туда).
- Одно и то же предупреждение звучит не чаще примерно одного раза в 4,2
  игровых секунд.

## 1. Выделение объектов

### 1.1. Начало выделения

Когда игрок начинает выделять (рамкой или одиночным кликом):

1. Скрипт вызывает `GameManagerBeginSelection` — программный интерфейс движка
   подготавливает буфер выбранных объектов.
2. `GameManagerStartSelection(mode)` запускает режим:
   - `spmRunTime` — для одиночного щелчка (один кадр);
   - `spmFrame` — для рамки выделения (каждый кадр, пока кнопка
     зажата).
3. Каждый кадр рамки скрипт зовёт `_control_*` функцию для обхода
   объектов и помечает попавших через `SetGameObjectPickedByHandle`.

### 1.2. Какие объекты могут быть выбраны

Функция
`SetGameManagerSelectionSettings(pickgroups, pickgamemanagerplayer, pickplayableObject, ...)`
принимает следующие параметры:

| Параметр | Что |
|---|---|
| `pickgroups` | Можно ли выделять группы (отряды). |
| `pickgamemanagerplayer` | Можно ли выделить только своих или всех. |
| `pickplayableObject` | Только управляемые юниты и здания, без декоративных персонажей. |

Для человека обычно используются `pickplayableObject = True` и фильтр
его собственного игрока. ИИ и редактор могут менять эти параметры.

### 1.3. Команды селекции

Скриптовые функции в `lib/control.script`:

| Функция | Что |
|---|---|
| `_control_SelectAllUnits(bBuildings, bExcludePeasants)` | Выделить всё доступное на карте (`Ctrl+A`). |
| `_control_SelectAllShips()` | Все корабли. |
| `_control_SelectAllPeasants()` | Все крестьяне. |
| `_control_SelectIdlePeasants()` | Простаивающих крестьян (без ордера). |
| `_control_SelectIdleMines()` | Шахты с местом для крестьян. |
| `_control_DeselectAllUnits(bUpdateSelection)` | Сбросить выделение. |
| `_control_GetUnitUnderCursor()` | Вернуть дескриптор юнита под курсором. |
| `_control_SelectOnlySquad()` | Оставить только отряды. |

**Группы управления** (`Ctrl+1` … `Ctrl+9`) на уровне скриптов
**не представлены отдельными функциями**. Вероятно, движок обрабатывает
их через функции `SetGUIEventStateOn*`.

## 2. Ввод: мышь, скролл, клавиатура

### 2.1. События мыши

| Функция движка | Что регистрирует |
|---|---|
| `SetGUIEventStateOnMouseDown(state)` | Состояние интерфейса при нажатии кнопки мыши. |
| `SetGUIEventStateOnMouseUp(state)` | Состояние при отпускании кнопки. |
| `SetGUIEventStateOnMouseMove(state)` | Состояние при движении мыши. |
| `SetGUIEventStateOnMouseWheel(state)` | … при скролле. |
| `SetGUIEventStateOnMouseEnterGUI(state)` / `OnMouseLeaveGUI(state)` | Когда курсор входит в элемент интерфейса или покидает его. |

Обработчики ввода переключают состояния интерфейса. Все они
регистрируются единым семейством функций `SetGUIEventState*`.

### 2.2. Получение текущего ввода

| Функция | Возвращает |
|---|---|
| `GetGUICurrentMouseCoord(var ax, ay)` | Текущие пиксельные координаты курсора. |
| `GetGUIPreviousMouseCoord(var ax, ay)` | Предыдущие (для дельты). |
| `GetCurrentMouseWorldCoord(var x, y, z)` | Координаты в мировом пространстве, найденные лучом от курсора к земле. |
| `GameObjectRayCastMouseRay()` | Выпускает луч от курсора в игровой мир и возвращает объект под курсором. |
| `GetGUIElementUnderMouse()` | Какой элемент интерфейса находится под курсором. |
| `GetGUIMinimapUnderMouse()` | Является ли курсор над миникартой. |

Ключевая функция: **`GetRayCastIntersectGameObjectFromMouseRay()`**
— строит луч из текущего положения курсора и возвращает **первый игровой
объект**, в который луч попал. Это и есть то, по чему щёлкнул игрок: юнит
или здание.

### 2.3. Скролл колеса

`GetGUIEventMouseWheelDelta()` — возвращает дельту последнего
скролла (положительная = вверх, отрицательная = вниз). По
умолчанию используется для приближения камеры:
- `SetCameraControlMouseWheelDistance(True)` — колесо меняет
  дистанцию.
- `SetCameraControlMouseWheelRotate(True)` — колесо поворачивает.

Только один из режимов активен. Профильные настройки через
`gProfile.*` — игрок может сменить.

### 2.4. Клавиатура

Прямого вызова `OnKeyDown` в скриптах **не нашлось** — обработка
горячих клавиш делается на стороне **движка** через переключение
состояний интерфейса (имена типа `OnKey_F1`, `OnKey_Ctrl_A`
регистрируются нативно).

Это значит, переназначить горячую клавишу через скрипт нельзя; нужно
менять двоичный код или настройки `editor.exe`.

## 3. Курсор

| Функция | Что |
|---|---|
| `GUIGetCursorPos(var screenx, screeny)` | Текущие координаты в экранных пикселях. |
| `GUISetCursorPos(screenx, screeny)` | Программно переместить курсор. |
| `GUIShowCursor(show)` | Скрыть / показать. |
| `SetClipCursor(val)` | Удерживать курсор внутри окна (для рамки выделения). |
| `SetGUICursorByName('cursor_name')` | Сменить визуал курсора. |

Курсорные образы — в `data/cursors/` (см.
[структуру игровых данных Cossacks 3](../../../internals/data/layout.md)).
Например, при наведении на врага курсор меняется на «меч» — это
смена через `SetGUICursorByName('attack')`.

## 4. Камера

### 4.1. Управление

| Функция | Что |
|---|---|
| `SetCameraMouseRotateFactor(val)` | Чувствительность вращения. |
| `SetCameraMouseDistanceSpeed(val)` | Скорость зума. |
| `SetCameraControlMouseWheelDistance(b)` | Колесо = зум (по умолчанию `True`). |
| `SetCameraControlMouseWheelRotate(b)` | Колесо = поворот (по умолчанию `False`). |
| `MoveCameraToPosition(x, z, time)` | Плавное движение к точке (`time` в игровых секундах). |
| `MoveCameraToUnitsListCenter(list)` | К центру списка юнитов. |
| `MoveCameraToSelectedUnits()` | К выделенным (двойной-клик-на-портрет в C&C). |

Игрок прыгает к группе цифрой (1–9) через `_control_MoveCameraTo*`
+ выделение.

### 4.2. Точка прослушивания звука

Звук в C3 рассчитывается относительно **точки прослушивания** — невидимой
точки, к которой привязан источник «уха» игрока:

- `GetSoundManagerListenerHandle()` — дескриптор точки прослушивания.
- `GetUseSoundManagerListenerAsCamera()` — `True`: точка
  привязана к камере (вы слышите то, на что смотрите).
- `GetUseSoundManagerListenerAsObject()` — точка привязана к
  объекту (например, к выбранному юниту).
- `SetPosSoundManagerListenerAsObject(x, y, z)` — программно
  поставить точку прослушивания в заданное место.

В обычной случайной партии точка прослушивания совпадает с камерой.
Поэтому игрок слышит то, что
рядом с **камерой**, а не с выделенным юнитом или базой.

## 5. Звуки и туман войны — две независимые системы

Это критическая деталь, **которую часто понимают неправильно**.

### 5.1. Как создаётся звук юнита

Когда юнит совершает действие (выстрел, шаг, бой, смерть), скрипт
зовёт `SndGetOrCreateSound(emittertag, 'units', owner)` — нативная
функция создаёт источник звука на координатах **объекта-владельца**
(`owner`). Параметры источника:

| Параметр | Что |
|---|---|
| `SetSndSoundMaxRadius(maxradius, sound)` | Радиус слышимости в мире. |
| `SetSndSoundMinDist(value, sound)` / `MaxDist` | Расстояние полной и нулевой громкости с линейным затуханием. |
| `SetSndSoundMaxRadiuses(rmaxvolume, radius, sound)` | Радиус 100 % громкости + общий радиус. |
| `SetSndSoundLoop(value, sound)` | Зацикленный звук (фоновый). |
| `SetSndSoundKillSndOutRad(value, sound)` | Остановить звук, если точка прослушивания вне радиуса. |
| `SetSndSoundConeOutsideVolume`, `InsideConeAngle`, `OutsideConeAngle` | Направленный звук. |

Решение «играть или нет» зависит от **расстояния до точки
прослушивания**. **Проверок тумана войны в этих функциях нет.**

### 5.2. Что это значит

- **Скрытый туманом войны вражеский юнит** **слышен**, если
  он попадает в радиус слышимости (`SetSndSoundMaxRadius`).
- Например: вражеский мушкетёр стреляет в скрытом лесу — вы
  **слышите выстрел**, но **не видите** ни юнита, ни вспышку.
- Это даёт игроку **акустическую разведку**: можно по звукам
  определить, что вражеский отряд зашёл с фланга, ещё до того как
  его увидит ваш скаут.

### 5.3. Почему так сделано

Два технических решения:

1. **Одна точка прослушивания — камера** в стандартном режиме. Туман
   войны считается отдельно для каждого игрока, а звук — относительно
   одной точки. Фильтрация каждого источника по видимости потребовала бы
   дополнительных вычислений.
2. Звук распространяется независимо от того, виден ли его источник.

См. также [«Обзор и туман войны»](../world/combat/vision_and_fow.md).

## 6. Предупреждения

Сигнал «обратите внимание» [^1] срабатывает, когда:

- юнит игрока атакован;
- здание игрока захватывают;
- происходит другое событие, для которого предусмотрено предупреждение.

### 6.1. Условия срабатывания

Игра последовательно проверяет, что предыдущее предупреждение уже
закончилось, событие касается текущего игрока, а объект находится вне поля
зрения камеры. Поэтому при атаке на базу, которую игрок сейчас видит,
дополнительного сигнала не будет.

### 6.2. Лимит частоты

После срабатывания следующие события блокируются примерно на 4,2 игровой
секунд, чтобы длительный бой не повторял сообщение каждый такт.

### 6.3. Что игрок видит и слышит

| Что получает игрок | Как это выглядит |
|---|---|
| Звуковой сигнал | Труба или боевой клич. |
| Визуальный сигнал | Мигающая рамка по краю экрана. |
| Направление | Стрелка к месту события. |

Игрок может переместить камеру к месту горячей клавишей: двойным пробелом
или `Ctrl+W` в зависимости от профиля.

### 6.4. Когда предупреждения нет

- **Атаки на не-владельца.** `_misc_DoAlarm` проверяет
  `plIOHnd = trgPlHnd or plIOHnd = plHnd`. Союзник в команде по
  умолчанию **не получит предупреждение** об атаке союзника — у каждого
  свой `plIO`.
- **Атаки священника** (он в `bpriest` — лечит, не атакует).
  Скрипт пропускает вызов предупреждения в `_misc_DoDamage`, если атакующий
  — священник.

## 7. Настройка горячих клавиш

Горячие клавиши хранятся в отдельном профиле. Одна запись связывает
клавишу с действием, при необходимости задаёт запасную комбинацию,
срабатывание по отпусканию и повторный перебор целей. Буквальный формат
записи приведён в [источниках](#источники).

### 7.1. Структура записи

| Поле | Что |
|---|---|
| `Key` | Основная клавиша или комбинация (`A`, `Ctrl+A`, `Ctrl+Alt+A`, `Shift+Z` и т. п.). Пустое значение означает, что горячая клавиша не назначена по умолчанию. |
| `AlternativeKey` | Запасная комбинация (опционально). |
| `Action` | Описание действия в формате `<тип>\|<параметр>`. |
| `Repeat` | Если `True`, повторное нажатие циклирует через варианты (например, `select|allunits` → следующий выделенный отряд того же типа). |
| `Up` | Если `True`, действие срабатывает по отпусканию клавиши, не по нажатию. |

### 7.2. Шесть видов действий (`Action`)

| Тип | Что делает | Примеры |
|---|---|---|
| `build` | Поставить здание из меню постройки | `build\|%nat%cen` (Городской центр), `build\|%com%mil` (Мельница). `%nat%` подставляется по текущей нации, `%com%` — по её группе (`eur` / `rus` / `tur` …). |
| `unit` | Команда выбранным юнитам | `unit\|attack`, `unit\|standground`, `unit\|nostandground`, `unit\|guard`, `unit\|cancelguard`, `unit\|attackpoint`, `unit\|enableattack`, `unit\|disableattack`, `unit\|stop`, `unit\|unloadall` |
| `squad` | Команды отряду | `squad\|fill`, `squad\|disband`, `squad\|rank` (линия), `squad\|column`, `squad\|square` |
| `select` | Выделение по фильтру | `select\|allunits`, `select\|allships`, `select\|allbuildings`, `select\|allpeasants`, `select\|idlepeasants`, `select\|idlemines`, `select\|militaryunits`, `select\|unitsofsametype`, `select\|addunitsofsametype`, `select\|allunitsofsametype`, `select\|addallunitsofsametype` |
| `interface` | Действие интерфейса | `interface\|minimap` (свернуть/развернуть миникарту), `interface\|viewcollision` (отладочная сетка столкновений). |
| `event` | Переход состояния интерфейса | `event\|eventmainmenu\|bcampaign` (открыть кампанию), `event\|eventmainmenu\|brandommap` и т. д. |

### 7.3. Горячие клавиши по умолчанию (фрагмент)

| Клавиша | Действие |
|---|---|
| `A` | Атака с продвижением (`unit\|attack`) |
| `S` | `unit\|standground` |
| `C` | Снять приказ стоять насмерть (`unit\|nostandground`) |
| `G` | `unit\|guard` |
| `R` | `unit\|attackpoint` (артиллерийская стрельба по точке) |
| `F` | `squad\|fill` (пополнить отряд) |
| `J` / `K` / `L` | `squad\|rank` / `squad\|column` / `squad\|square` |
| `Ctrl+S` | `unit\|stop` |
| `U` | `unit\|unloadall` (выгрузить из транспорта / гарнизона) |
| `Z` | Следующий юнит того же типа (`select\|unitsofsametype`, повторяемая команда) |
| `Shift+Z` | `select\|addunitsofsametype` |
| `Ctrl+A` | `select\|allunits` |
| `Ctrl+B` | `select\|allbuildings` |
| `Ctrl+M` | `select\|idlemines` |
| `Ctrl+P` или клавиша обратного апострофа | `select\|idlepeasants` |
| `Ctrl` с обратным апострофом | `select\|allpeasants` |
| `Ctrl+Q` | `select\|allships` |
| `Ctrl+Alt+A` или `Ctrl+Shift+A` | `select\|militaryunits` |
| `Q` | `interface\|viewcollision` |
| `Alt+M` | `interface\|minimap` |

Есть и большой набор `build|...`: по одной букве для каждого здания.
Например, `C` — Городской центр (`Cen`), `H` — Дом (`House`), `B` —
Казарма (`Bar`), `L` — Кузница (`Bla`), `E` — Академия (`Aca`), `S` —
Конюшня (`Sta`), `D` — Дипломатический центр (`Dip`), `M` — Рынок
(`Mar`), `T` — Башня (`Tow`), `P` — Порт (`Por`).

> **Дубликаты** разрешены: `S` встречается у `build|sta`, `unit|standground`
> и `event|eventmainmenu|bsettings`. Контекст разрешения — какое
> текущее состояние интерфейса: игра, выбранный юнит или открытое меню.

## 8. Клавиши, которые нельзя переназначить

Файл `data/gui/menu.inc/hotkeysettings.inc` содержит два списка
`forbiddenkeys` (нельзя поставить как одиночную клавишу) и
`forbiddencombokeys` (запрещённые комбинации). Это и есть «движковые»
горячие клавиши, которые не настраиваются через интерфейс, потому что встроены в
поведение игры.

### 8.1. Одиночные зарезервированные клавиши

| Клавиша | Зарезервирована за |
|---|---|
| `LButton`, `RButton`, `MButton` | Кнопки мыши — выделение, приказ и перетаскивание камеры. |
| `Left`, `Right`, `Up`, `Down` | Скролл камеры по сторонам света. |
| `Space` | Переместить камеру к последнему предупреждению. |
| `Return` (`Enter`) | Открыть чат в сетевой игре. |
| `Escape` | Закрыть интерфейс или отменить строительство / атаку с продвижением. |
| `Shift`, `Ctrl`, `Alt` и варианты отпускания | Модификаторы — нельзя переназначить как одиночные. |
| **`0`, `1`, …, `9`** | **Выделить группу управления.** |
| **`NUM0`–`NUM9`** | Те же цифры на цифровой клавиатуре. |
| `F5`, `F7`, `F10` | Быстрое сохранение, загрузка и отладка. |
| `PrintScreen0/1/2` | Снимок экрана (стандартное Windows-поведение). |
| `Sub`, `Add`, `-`, `=` | Скорость игры: медленно (`slow`) / быстро (`fast`). |
| `PGUP`, `PGDN`, `Home`, `Del`, `Back` | Навигация по логу / удаление. |
| `P` | Пауза. |
| `[`, `]` | Прокрутка предупреждений. |

### 8.2. Зарезервированные комбинации для групп и системы

**Группы управления (10 штук, цифры 0–9):**

| Комбинация | Что |
|---|---|
| **`Ctrl+0` … `Ctrl+9`** | **Назначить** текущее выделение группе с соответствующим номером. |
| **`Shift+0` … `Shift+9`** | **Добавить** текущее выделение в группу с соответствующим номером. |
| **`Alt+0` … `Alt+9`** | **Выделить** группу с соответствующим номером. |
| **`Shift+Alt+0` … `Shift+Alt+9`** | Дополнительный режим, предположительно добавляющий группу к текущему выделению. |

То есть в Cossacks 3 есть **10 групп управления** (0–9).

**Камера и системные:**

| Комбинация | Назначение |
|---|---|
| `Alt+F4` | Закрыть приложение. |
| `Ctrl+S` | Быстрое сохранение. |
| `Ctrl+Tab` | Переключение игрока при наблюдении или просмотре реплея. |
| `Ctrl+Home` | Центрировать камеру на стартовую точку игрока. |
| `Ctrl+PGUP` / `Ctrl+PGDN` | Прокрутка вкладок интерфейса или переключение игрока. |
| `Ctrl+W`, `Ctrl+F` | Быстрый переход камеры, предположительно к Городскому центру или выделению. |
| `Ctrl+Add` / `Ctrl+Sub` | Приблизить / отдалить. |
| `Ctrl+Shift+P` | Режим отладки. |
| `Ctrl+T` | Командный чат, отдельно от обычного чата по `Return`. |
| `Alt+Mul` (звёздочка цифровой клавиатуры) | Сменить режим миникарты. |
| `Shift+Alt+Mul` | Расширенный режим миникарты. |

### 8.3. Классы групп, найденные в `RTTI`

В таблице типов исполняемого файла найдены классы `TXGroup4`
(возможно, один из десяти) и
`TXGroupSelectionViewer` — последний рисует **зелёные подсветки**
вокруг юнитов, входящих в активную группу управления. Реализация
привязки групп на скриптовом уровне отсутствует
(`SetGUIEventStateOnKeyDown` в `lib/*.script` зовётся только для
`'EventMultiplayerChat'`). Значит обработка цифровых клавиш для
групп управления выполняется **в двоичном коде игры**, без вызова скриптов.

## 9. Игровой темп и пауза

### 9.1. Скорость игры

`_control_GetGameSpeedMode` / `_control_SetGameSpeedByMode`:

| Режим | Значение |
|---|---:|
| `slow` (0) | 7 тиков/сек |
| `normal` (1) | 10 тиков/сек |
| `fast` (2) | **14 тактов/с** (по умолчанию в случайной партии) |

Горячие клавиши: `Ctrl+Add` / `Ctrl+Sub` на цифровой клавиатуре — обе
зарезервированы (см. §8.2).

### 9.2. Пауза

Клавиша `P` зарезервирована (см. §8.1). Лимит — **4 паузы по 120
секунд** на партию.

## 10. Доступ скрипта к клавиатуре

Функции движка для проверки клавиш [^2]:

| Функция | Что |
|---|---|
| `IsKeyDown(vk: Integer): Boolean` | Нажата ли клавиша с заданным виртуальным кодом. |
| `IsKeyDownByName(sname: String): Boolean` | По имени (`'Ctrl'`, `'Shift'`, `'A'`). |
| `KeyPressed(minvkcode: Integer): Integer` | Код последней нажатой клавиши с `vkcode >= minvkcode`. |

В скриптах **не вызываются** вообще — обработка ввода идёт
полностью через переключение состояний интерфейса функциями
`SetGUIEventStateOn*`. Скриптам проверять «нажат ли `Shift`» обычно
не нужно, потому что состояние интерфейса
уже учитывает модификаторы.

## 11. Открытые вопросы

1. **Точное действие `Shift+Alt+0..9`.** Список запрещённых комбинаций
   подтверждает, что комбинация зарезервирована, но что она делает —
   не вычитано из кода.
2. **Звук союзника за туманом войны.** Если юнит союзника скрыт
   туманом для вас, но виден самому союзнику, слышен ли он? Предположительно
   да: звук зависит от расстояния до точки прослушивания.
3. **Точная длительность задержки предупреждения.** Порог равен 135
   внутренним единицам, что при пересчёте через 32 кадра даёт около
   4,22 игровой секунды. Проверить измерением, что счётчик предупреждения
   использует именно эту шкалу.
4. **Двойной-клик на портрет юнита** — прыгает ли камера? В коде
   `MoveCameraToSelectedUnits` есть, но триггер не уточнён в
   скриптах.
