# Строительство, ремонт и разрушение зданий

[← Как устроена игра](../../README.md)

Разбор размеров зданий, постройки и ремонта крестьянами, стен,
внутренних мест, захвата и разрушения. Все ссылки на код и фрагменты
на языке Pascal собраны в разделе
[Источники](#источники) в конце документа. Все пути там относительно `data/` в
установке «Казаков 3».

> **Технические детали анимации `construct` и точные покадровые интервалы** —
> в [описании системы анимаций](../../../../internals/engine/animation_system.md).

## Коротко о главном

- **Время постройки** (`buildtime`) для зданий хранится с дополнительным множителем
  `gc_buildtime_modifier = 10` [^1]. У юнитов множитель = 1. Реальное время
  постройки = `frames × 10 / 32`, а не `frames / 32`. В `docs/data.json` поле
  `building.buildtime_sec` уже учитывает ×10.
- **Занимаемая площадь** задаётся маской столкновений в файле
  `<sid>.prop`. Размер ячейки — 0,5 клетки (`gc_collision_size = 0.5`).
- **Ремонт бесплатен** и восстанавливает 20 единиц прочности за
  один удар крестьянина (`gc_gameplay_repairhp`).
- **Постройка**: `delta = 0.359 / buildtime` за удар. Анимация
  `construct` = 13 кадров = 0,406 игровой секунды.
- **Места для строителей** для выпуклой формы равны
  `bbox_cols + bbox_rows`; предел движка — 30. У обычного сегмента
  стены четыре места.
- **Радиус захвата** (`captureradius`) равен четырём клетким
  (см. [механику захвата](capture_mechanics.md)).

## 1. Форма и занимаемая площадь здания

**Источник:** `collisionmaskproperty.Mask` в `.prop`-файле здания [^2].

**Единица:** одна ячейка маски = **0,5 клетки** (`cellSize := 0.5` [^3]).

**Маска — двумерная текстовая сетка из 0 и 1**, где 1 означает
занятую клетку. Пример Городского центра Баварии (`bavcen`):

```
000110000000          12 столбцов × 11 строк = 6×5,5 клетки
001111000000          ↓ заполненный диамант
011111100000
111111110000
011111111000
001111111110
000111111110
000011111100
000001111000
000000110000
000000000000
```

Занято примерно 57 ячеек × 0,5² = 14,25 клетки². Визуально — диагональный квадрат.

**Граница модели** (`CustomBoundingAABB`) для отрисовки и выбора
отличается от маски столкновений и обычно меньше. Для `bavcen`:
`X = 4,45`, `Z = 2,70` клетки.

**Масштаб маски** (`ScaleFactor`) равен 1 [^4]: её ячейки не
масштабируются. Визуальный `DefaultScale=0.662` не влияет на столкновения.

**Где хранится у нас:** пока нигде; маски из `.prop` ещё предстоит
извлечь в `JSON`.

## 2. Бесплатный ремонт

**Источник:** обработчик окончания анимации `construct` проверяет тип приказа и
прибавляет фиксированное количество прочности, не превышая `maxhp` [^5].

**Константа:** `gc_gameplay_repairhp = 20` [^6].

**Механика:**

- Каждый завершённый цикл анимации `construct` восстанавливает 20
  единиц прочности здания.
- **Никаких ресурсов не тратится.** Ремонт абсолютно бесплатен.
- Прочность не превышает `maxhp`.
- Несколько крестьян ремонтируют параллельно в доступных местах
  вокруг здания (см. §3.3).

**Анимация строительства:** 13 кадров (186–198 в `AAF`). При 32 кадрах
в секунду один цикл занимает 0,406 игровой секунды.

**Расчёт скорости ремонта:**

- Один крестьянин: 20 / 0,406 = **49,3 прочности в игровую секунду**.
- N крестьян: 49,3 × N, пока не заняты все доступные места.
- Городской центр Баварии (`bavcen`) с прочностью 4 000:
  примерно **81 игровая секунда** одним крестьянином.
- Двенадцать строителей справятся примерно за **6,75 игровой секунды**.

⚠ Ремонт работает только когда здание **уже достроено** (`bbuilt = True`). До завершения постройки действует другой механизм (см. §3).

## 3. Постройка крестьянами

### 3.1 Прогресс за один «удар молотком»

Расчёт `delta`, `buildprogress` и прибавки прочности выполняется при каждом завершении
анимации `construct` [^7]:

- `delta := gc_buildtime_progressperhit / buildtime`
- `buildprogress += delta`
- `hp += round(maxhp × delta)`, но не выше `maxhp`

Где `gc_buildtime_progressperhit = 10 × 1/32 × 1.15 = 0.359375`.

### 3.2 Время постройки и число строителей

**Каждый крестьянин-строитель** независимо проигрывает анимацию
`construct`: 13 кадров при 32 кадрах в секунду, то есть 0,406 игровой
секунды за цикл. В конце цикла засчитывается один удар.

**Формула для N строителей:**

```
hits_total = buildtime_g_sec / 0.359375
T_with_N(g-sec) = hits_total / (N / 0.406)
                = buildtime_g_sec × (0.406 / 0.359)/ N
                = buildtime_g_sec × 1.13 / N
```

**Практическое правило:** `time = buildtime × 1.13 / N`. Удвоение
числа крестьян примерно вдвое сокращает время.

**Предел:** N ограничено числом доступных мест (см. §3.3), но не
может превышать 30.

**Пример: Казарма 18 века Баварии (`bavba2`,
`buildtime = 5625` игровых секунд):**

| Строителей | Игровые секунды | Игровые минуты |
|---:|---:|---:|
| 1 | 6 356 | 105,9 |
| 2 | 3 178 | 53,0 |
| 5 | 1 271 | 21,2 |
| 10 | 636 | 10,6 |
| 16 | 397 | **6,6** |

На практике большое здание редко строит один крестьянин. После
размещения фундамента свободные крестьяне поблизости занимают
доступные места вокруг него.

Полная таблица «время с N крестьян» по всем зданиям всех наций — в
[отчёте о времени строительства](../../../reports/economy/construction_times.md)
(генератор: [`compute/compute_construction_times.py`](../../../../compute/compute_construction_times.py)).

**Что хранится в `JSON`:** `building.buildtime_sec = frames × 10/32` —
это нормированное время `objbase.buildtime`. Для одного строителя
фактическое время примерно равно `buildtime_sec × 1.13`, а для N
строителей результат дополнительно делится на N.

### 3.3 Сколько крестьян могут строить одновременно

**Предел:** `gc_MaxBuilderCount = 30` [^8].
**Минимальный интервал:** `gc_BuilderDist = 1.0` клетка [^9].

**Места для строителей** — конкретные позиции вокруг здания, где
крестьянин стоит и работает.

**Источник позиций:**

1. Для большинства зданий они **динамически вычисляются** по маске
   столкновений через `_unit_CalcBuilderPoints` [^10]. Алгоритм обходит
   периметр с шагом 0,5 клетки и ставит точку через одну клетку.
2. Для стен места заданы в `data/game/var/wallcustom.cfg`, до 16 на вариант.
3. `data/game/var/objcustom.cfg` допускает переопределение, но сейчас
   содержит только `ExitPoints`, `SmokePoints` и `Decal`.

**Точные значения для каждого здания:** [отчёт о местах строителей](../../../reports/economy/builder_slots.md)
и [`derived/builder_slots.json`](../../../../derived/builder_slots.json) —
генерируются [`compute/compute_builder_slots.py`](../../../../compute/compute_builder_slots.py).

**Геометрическое правило.** Для выпуклой формы — диска, ромба или
скруглённого прямоугольника — манхэттенский периметр равен
`bbox_cols + bbox_rows`. Обходчик маски даёт тот же результат.

**Невыпуклых зданий** мало: 5 из примерно 350. Это Городские центры
Шотландии (`scocen`) и Швеции (`swecen`), Соборы Португалии
(`portem`) и Украины (`ukrtem`), а также баварский Дом (`bavhou`).
Обходчик учитывает внутренние выемки; для `swecen` 27 мест
подтверждены в игре.

**Полная таблица эмпирических точек** (9 из 10 совпадают с расчётом):

- Выпуклые: `polcen=18`, `ruscen=24`, `eurmil=10`, `rusmil=7`,
  `polbla=18`, `polba2=25` ✓
- Невыпуклый Городской центр Швеции: `swecen=27` ✓
- Разреженные Склады: `tursto=8`, `spasto=7`, `russto=8` ✓
- Известное расхождение: для `eursto` расчёт даёт 9, измерение — 8.

**Сильная зависимость от нации.** Размер маски (а значит и периметр)
у одной и той же категории здания может различаться кратно. Пример для
Казармы XVIII века (`*ba2`):

| Нации | Маска | Занятые ячейки | Периметр, клетки | Места |
|---|---|---:|---:|---:|
| Венеция (`ven`) | 12×9 | 58 | 19 | **19** |
| Саксония (`sax`) | 12×9 | 59 | 20 | **20** |
| Нидерланды (`net`) | 12×10 | 69 | 21 | **21** |
| Швейцария, Пьемонт, Пруссия, Дания | 12×12 | 63–91 | 22 | **22** |
| Бавария, Англия | 12×11 | 65–73 | 23 | **23** |
| Португалия (`por`) | 12×14 | 86 | 24 | **24** |
| Польша (`pol`) | 14×14 | 87 | 25 | **25** |
| Испания, Венгрия | 14×13 | 101–103 | 26 | **26** |
| Швеция (`swe`) | 14×13 | 108 | 27 | **27** |
| Австрия, Франция | 16×15–17 | 112–129 | 29 | **29** |
| Шотландия, Россия | 16×15–18 | 123–133 | 30+ | **30** |

**Особенность разреженных масок Складов.** У `russto`, `eursto`,
`spasto` и `tursto` маска невыпуклая. Обычный обход верно даёт 8 мест
для `tursto` и 7 для `spasto`. У `russto` и `eursto` остаются две
раздельные линейные опоры, поэтому игра обходит общий прямоугольник.
Правило «для линейных компонентов использовать
`bbox_cols + bbox_rows` объединения» точно даёт 8 мест для `russto`
и ошибается на единицу для `eursto`. В вычислителе это метод
`bbox_union`.

**Ворота — мгновенное индивидуальное улучшение существующей стены**
(`gc_upg_type_single_buildgate`), а не отдельное здание. Игрок выбирает
прямой участок минимум из трёх сегментов. Центральный сегмент заменяется
воротами (`*sga` / `*wga`) с `individual.upglevel = 1`; следующий
`_unit_ControlBuildProgress` сразу устанавливает полную прочность, а
`OnTagStates` переводит объект в `bbuilt = True`.

**Расхождение расчёта и игры на единицу.** Помимо `eursto`,
вычислитель даёт 23 места для `bavba2`, а старое игровое измерение —
22. Возможные причины: одна недостижимая точка или близость края карты.

### 3.4 Алгоритм назначения крестьянина на стройку

`_unit_OrderBuild` [^11]:

1. Получает список мест для строителей.
2. Для каждого места проверяет, занято ли оно другим строителем или
   ремонтником. Если да, место пропускается.
3. Из свободных выбирает **ближайший по евклидову расстоянию** к крестьянину.
4. Назначает крестьянину место и отдаёт техническую команду движения (`move`).
5. Крестьянин дойдя — начинает играть `construct` анимацию.
6. Каждый цикл анимации повышает прочность и прогресс (`progress`).

**Стоимость списывается целиком при закладке фундамента**, когда
крестьянин подходит к месту строительства. После этого ресурсы не тратятся.

## 4. Стены и ворота

**Тип:** `gc_obj_usage_hardwall` / `gc_obj_usage_weakwall`: Частокол,
деревянные и каменные ворота, каменная Стена.

**Сегмент стены** занимает **2×2 клетки**. Это подтверждают координаты
мест строителей в `wallcustom.cfg`: от −1 до +1 относительно центра.

**Места для строителей по вариантам сегмента:**

| Вариант | Геометрия | Места |
|---:|---|---:|
| 1 | вертикальная стена | 4 (2 точки слева + 2 справа) |
| 2 | горизонтальная | 4 (2 сверху + 2 снизу) |
| 3 | угол / диагональ | 4 |
| 4 | угол / диагональ (зеркальная) | 4 |
| 5 | пересечение или ворота | **12** (12 точек по периметру 2×2) |
| 6+ | прочие | 4-8 |

Предел движка: `gc_MaxWallBuilderPointsCount = 16` [^12].

**Параметры стен** (`buildtime_g_sec = frames × 10/32`, см. конвенцию зданий):

| Стена или ворота | Внутренний идентификатор | Прочность | Кадры | Игровые секунды | Цена | Потребление камня |
|---|---|---:|---:|---:|---|---:|
| Каменная Стена | `eurswa` | 50 000 | 288 | **90** | 50 камня | 250 |
| Каменные ворота | `eursga` | 32 000 | 288 | **90** | 50 камня | 250 |
| Каменная Стена России | `russwa` | 50 000 | 640 | **200** | 60 камня | 200 |
| Каменные ворота России | `russga` | 32 000 | 640 | **200** | 60 камня | 200 |
| Каменная Стена Турции и Алжира | `turswa` | 50 000 | 384 | **120** | 60 камня | 150 |
| Каменные ворота Турции и Алжира | `tursga` | 32 000 | 384 | **120** | 60 камня | 150 |
| Частокол | `ukrwwa` | 1 500 | 18 | **5,6** | 10 дерева | 32 |
| Частокол Украины | `ukrwwa` | 2 500 | 26 | **8,1** | 12 дерева | 40 |
| Деревянные ворота | `ukrwga` | 1 000 | 18 | **5,6** | 10 дерева | 32 |
| Деревянные ворота Украины | `ukrwga` | 1 500 | 26 | **8,1** | 12 дерева | 40 |

При `costpercent = 0` все сегменты стоят одинаково. Поля
`consume.stone` и `consume.wood` задают постоянное потребление ресурса,

Время постройки сегмента силами N строителей равно `bt × 1.13 / N`,
но N ограничено `gCustomBuildPointsWall[wallvariation].builderCount`.

## 5. Юниты внутри зданий

### 5.1 Места для крестьян в шахтах (`peasantabsorber`)

Шахты `eurgol`, `euriro`, `eurcoa` вмещают пять крестьян
(`peasantabsorber=5`) без улучшений и до 95 после них. Подробнее —
в [разборе добычи](peasant_extraction.md#5-шахты-золото-железо-и-уголь).

### 5.2 Вместимость транспорта (`transport`)

Грузоподъёмность для транспортных юнитов:

- Транспорт (`ferry`): `transport = 80+40 = 120` мест [^13].
- Другие транспортные корабли ещё требуют отдельной проверки.

### 5.3 Башня как самостоятельное орудие

Башня не имеет гарнизона (`peasantabsorber=0`, `transport=0`). Она
сама является неподвижным артиллерийским зданием. Базовые параметры
европейского варианта [^14]:

| Параметр | Значение |
|---|---|
| Тип снаряда (`weapon[0].kind`) | `gc_obj_weapon_kind_cannonball` |
| Урон (`weapon[0].damage`) | 1000 |
| Пауза (`weapon[0].pause`) | 400 кадров = 12,5 игровой секунды |
| Минимальная / максимальная дальность (`radiusmin`, `radiusmax`) | 550 / 1500 пикселей |
| Максимальная дальность в клетках | ≈ 28,1 |
| Радиус обнаружения (`detectradiusmin`, `detectradiusmax`) | 550 / 50 000 пикселей |
| Цена выстрела (`weapon[0].cost`) | 10 железа, 30 угля |
| Разброс (`weapon[0].dispertion`) | 100 пикселей |
| Радиус поиска (`searchradius`) | 1400 пикселей ≈ 26,25 клетки |
| Потребление золота (`consume.gold`) | **500 за такт = 0,8 золота в игровую секунду** [^16] |
| Прочность | 20 000 |
| Время постройки | 3 937 кадров ≈ 123 игровые секунды |
| Рост цены (`costpercent`) | 120 |
| `bturnoff=True` | Башню можно отключить, прекратив расход золота |

**Российский вариант** [^17]: прочность 21 000, `buildtime=4725`,
`costpercent=125`, защита 5, разброс 125 пикселей. Перезаписывается только
пауза: 300 кадров = 9,375 игровой секунды.

**Турецкий вариант** [^19]: прочность 22 500, `buildtime=3150`,
`costpercent=125`, цена 150 камня, 90 дерева и 100 золота. Урон 1 200,
пауза 500 кадров, дальность 1 600 пикселей, расход на выстрел — 40 угля и
15 железа.

**Улучшение:** `gc_ach_upgrade_towerattspeed` повышает скорострельность
и связано с достижением.

⚠ Помещать пехоту в Башню **нельзя**: в «Казаках 3» она стреляет сама.

**Ограничение данных:** оружие зданий пока извлекается не полностью — если у
постройки два вида оружия, в сводку попадает только первое. Технические
подробности — в [списке известных ограничений](../../../../internals/project/known_issues.md).

### 5.4 Другие проверки внутренних мест

- `bcapture=True` отмечает, что объект **может быть захвачен** врагом (см. §7).
- `gc_obj_usage_tower` — особый случай: проверка выполняется даже без
  `bcapture` [^20].

## 6. Ветшание и разрушение зданий

### 6.1 Ветшание

**Не найдено** в коде. Здания **не теряют прочность** со временем
сами по себе. Она меняется только от:

- Урон врагом
- Захват (?) — нужно проверить

### 6.2 Разрушение

При нулевой прочности здание переходит в состояние
`gc_statetag_essential_death`. Модели вроде `bavcen_death1a` и
`bavcen_death2a` показывают руины, но не являются отдельными игровыми
объектами.

**Возможно ли отстроить?** — нужно проверить специально (предположительно: нет, только новое здание ставить).

#### Последовательность разрушения

При `hp ≤ 0` или `bDie := True` здание получает `essential_death`.
Машина состояний [^27] запускает первый таймер `DelayExecuteState`:

- если здание было `essential_birth` (отмена недостроенного), через
  30 игровых секунд сразу выполняется `DeathStage2`;
- иначе через 30 игровых секунд выполняется `DeathStage1`, модель
  меняется на `<sid>_death1`, а ещё через 30 секунд — `DeathStage2`.
  Для Шахты (`usage = mine`) обе паузы удваиваются.

**Остов** в этом промежутке остаётся на карте: модель
`<sid>_death1.mesh`, состояние `essential_death`, материал `debris`
[^29] и прежняя коллизия. До его исчезновения строить на этих клетках
нельзя.

**Сброс клетки.** В `DeathStage2` [^30] для не-стен с `gc_collisiontag_terrain` вызывается `_unit_SetTerrainCollision(myHnd, gc_collisiontag_none)` + `_misc_UnitTopologyUpdate`, затем `GameObjectRequestToDestroyByHandle`. После этого клетка освобождается, и на ней можно ставить новое здание.

**Гарнизон внутри** (если у здания `peasantabsorber > 0` или `transport > 0`). `_unit_DestroyObj` [^31] собирает `gc_argunit_inside` и вызывает `_unit_DoUnitsGoOutside(list, bDead=True, ...)`. Эта процедура [^32] ставит каждому юниту в списке `essential_death`, то есть содержимое умирает вместе со зданием.

#### Возврат ресурсов из очереди при уничтожении

Перед самым удалением обработчик `OnDeath` [^33] прокручивает очередь
заказов здания:

- `produce`-заказы прогоняются через `_unit_ProduceUnit(... bState=False, ...)` [^34] — внутри ведёт к `_unit_CancelUnitProduction` и возврату ресурсов.
- Заказы улучшений (`performupgrade`) проходят через
  `_unit_CancelUpgradePerform`, возвращая базовую стоимость.

То есть при сносе работающей Казармы или Академии ресурсы за уже
оплаченные юниты и улучшения **возвращаются** игроку, а не сгорают.

#### Штраф к счёту

При разрушении владельцу: `−2 × building.score` (или `−5×`, если здание
ранее уже было захвачено — см. [условия победы](../../systems/victory_conditions.md)).

### 6.3 Возврат ресурсов при отмене заказов

| Действие | Возврат | Источник |
|---|---|---|
| Отмена недостроенного здания через интерфейс | **100 %** потраченных ресурсов | Обработчик `_misc_GUICancelBuilding` [^25] вызывает `GameObjectDestroyByHandle`; возврат, вероятно, выполняется движком, и подтверждён в игре. |
| Отмена заказа юнита в очереди | **100 %** списанной при заказе суммы | `_unit_CancelUnitProduction` [^24] возвращает `price[k] × costmodifier`; `restype` хранит число уже построенных экземпляров на момент заказа. Текущая цена не учитывается. |
| Отмена улучшения | **100 %** базовой стоимости | `_unit_CancelUpgradePerform` [^35] возвращает базовую стоимость из `_country_GetUpgradeCostBySID`; масштабирования `costpercent` у улучшений нет. |
| Захват | Все отменяемые заказы прерываются и ресурсы возвращаются **прежнему** владельцу. | См. `_misc_ChangePlayer` ветку очистки в [Как захватываются здания и юниты](capture_mechanics.md). |

### 6.4 Производство при низкой прочности

`doprogressorders.inc` не проверяет прочность. Здание производит юниты,
пока не разрушено. Недостроенное здание (`bbuilt=False`) не производит.

## 7. Захват зданий

**Условие проверки:** `objprop.bcapture = True` или роль
`gc_obj_usage_tower`.

**Механика** [^21]:

- Радиус: `gc_gameplay_captureradius = 214/53.33 = 4.0 клетки` [^22].
- Радиус блокировки огня: `gc_gameplay_captureblockshotradius = 3.0 клетки`.
- Если вражеская пехота находится в радиусе захвата здания и игрока-владельца **нет** в этом радиусе → здание переходит к врагу.
- **Захват мгновенный**, что подтверждено в игре 29 апреля 2026 года.
  Достаточно одной проверки с условием
  `enemy_in_radius && owner_not_in_radius`.

**Какие здания захватываются:** Шахты, Городские центры и многие
другие здания с `bcapture=True`.

**Стены и ворота — отдельная ветка.** У сегментов `bcapture = False`,
но в `_misc_CheckCapture` для всех `bwall` принудительно ставится
`bDie := True`: вражеский пехотинец без противодействия **уничтожает**
сегмент. При прочности ниже трети максимальной эта ветка пропускается.

При захвате:

- Прочность сохраняется.
- Владелец меняется на захватчика.
- Захватчик получает очки с множителем 5 [^23].

⚠ Тонкости: при захвате `counter.all` увеличивается, а `counter.built` —
нет. Это влияет на масштабирование цен: если захватили Городской центр,
следующий ваш центр будет стоить втрое дороже, потому что захваченный
учитывается в счётчике.

## 8. Резюме механик (быстрый ответ на частые вопросы)

| Вопрос | Ответ |
|---|---|
| Длина одного сегмента стены | 2×2 клетки; от 4 до 12 мест для строителей в зависимости от варианта (§4) |
| Можно ли переопределить места строителей в `objcustom.cfg`? | Сейчас файл содержит только `ExitPoints`, `SmokePoints` и `Decal`. Для зданий места считает `_unit_CalcBuilderPoints`, а у стен они явно заданы в `wallcustom.cfg`. |
| Ветшание прочности | **Нет.** Здания теряют прочность только от урона; `gc_decay` и `_hp_decay` в скриптах отсутствуют. |
| Исчезновение обломков | **Примерно через 60 секунд.** Цепочка состояний: `OnTagStates.essential_death` → `DeathStage1` → `DeathStage2` → `GameObjectRequestToDestroyByHandle`. Шахты исчезают вдвое медленнее. |
| Можно ли восстановить здание после нулевой прочности? | **Нет.** `OnDeath` вызывает `_unit_DestroyObj`; модель `<sid>_death1a/2a` — лишь визуальные руины. Нужно строить новое здание. |
| Радиус захвата универсален? | Да: `gc_gameplay_captureradius = 4.0` клетки [^22]. Отдельных значений для зданий не найдено. |
| Возврат при отмене постройки | Заказ юнита возвращает ровно списанную сумму через `_unit_CancelUnitProduction` [^24]. Отмена фундамента через `_misc_GUICancelBuilding` [^25] возвращает 100 % затрат; вероятно, это делает движок. |
