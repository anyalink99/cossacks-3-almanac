# Recon: голод и бунт

Глубокий разбор: при каких условиях у игрока поднимаются флаги
`bfamine` (голод) и `brebellion` (бунт), что именно при этом
происходит, кто умирает первым, как защититься. Все ссылки на код —
в [Источниках](#источники) в конце документа.

## TL;DR

- **Голод** (`bfamine = True`) включается, когда у игрока
  `food = 0` **и** на следующем тике потребления оказывается
  отрицательный остаток. Снимается, как только `food > 0` или
  `consume.food <= 0`.
- **Бунт** (`brebellion = True`) включается, когда у игрока
  `gold = 0` **и** `consume[gold] > income[gold]` (потребление
  превышает добычу). Снимается, как только `gold >= 2` или
  `consume[gold] <= 0`.
- Голод убивает обычных юнитов, у которых `bnohungry = False`
  (крестьяне, пехота). Здания, наёмники, ландскнехты не трогаются.
- Бунт уничтожает **только наёмников** (`bmercenary = True`) — со
  скоростью ≈ 18.3 % за тик на сложности hard+. См.
  [`mercenaries_diplomacy.md` §3](../../systems/mercenaries_diplomacy.md).
- Очки за уничтожение мятежного наёмника считаются с множителем
  `× 3` (не `× 2`), что делает рейды по голодающему противнику
  эффективнее в плане score [^1].

---

## 1. Где и когда поднимается флаг

Логика в `lib/player.script` — процедура потребления ресурсов,
вызывается каждый игровой тик [^2]. Для каждого ресурса:

- Если у игрока есть достаточная сумма (`res[i] >= value`) — ресурс
  списывается, флаг (`bfamine` или `brebellion`) сбрасывается в
  `False`.
- Если суммы не хватает — списывается остаток, и для `food` сразу
  поднимается `bfamine := True`. Для `gold` дополнительная
  проверка: `brebellion` поднимается только если
  `consume[gold] > income[gold]`.

То есть для **gold** есть «защита от заплатил-как-смог»: если
шахты окупают потребление наёмников, бунт не вспыхнёт даже при
`gold = 0`. Для **food** такой защиты нет: голод включается сразу,
как только `food = 0` и есть голодающие.

После расчёта в самом конце процедуры идёт авто-снятие флага: если
`brebellion = True`, но условие отпало (есть ≥ 2 gold **или**
потребление gold обнулилось) — флаг гасится. Аналогично для
`bfamine` — если food снова > 0 или потребление food = 0 [^2].

То есть **на одном и том же тике** флаг может зажечься и сразу
погаснуть — например, если ровно в этот же тик игрок продал на
рынке еду или принял караван. В UI это даст одиночное мигание
красным.

### 1.1. Период тика

Тик потребления ресурсов — `_player_DoTickResources` или подобный,
вызывается раз в **`_misc_GetTickRes()` секунды**, обычно ~1 g-сек
(см. [`internals/engine/ticks_and_subticks.md`](../../../../internals/engine/ticks_and_subticks.md)).
То есть флаг проверяется ≈ 14 раз в реальную секунду на скорости
fast.

## 2. Что происходит при голоде

`bfamine = True` запускает побочный механизм в
`lib/unit.script` — каждый тик все юниты проверяются на признак
«могут умереть от голода». Условия гибели:

| Условие | Результат |
|---|---|
| `bfamine = True` для игрока | Триггер. |
| `bnohungry = True` у юнита | Иммунитет (никогда не умрёт от голода). |
| `consume.food = 0` у юнита | Иммунитет (он еду не ест → его не за что наказать). |

Для подходящего юнита: каждый тик с RNG-вероятностью
(см. ниже §2.2) `hp := 0`, юнит умирает мгновенно.

### 2.1. Кто иммунен (`bnohungry = True`)

| Тип | `bnohungry` |
|---|---|
| Все здания | `True` |
| Наёмники (`bmercenary = True`) | `True` |
| Ландскнехты, отдельные элитные юниты | зависит, см. `data.json` |
| Крестьяне | `False` (умрут первыми) |
| Обычная пехота, кавалерия | `False` |

Точное значение `bnohungry` для каждого юнита — в
[`../../../../data.json`](../../../../data.json), поле `bnohungry`.

### 2.2. Вероятность гибели от голода

Точная формула — RNG-вентиль на тик с порогом по сложности
игрока [^3]:

| Difficulty | Threshold | Шанс смерти за тик | Ожидаемое время до смерти 1 юнита |
|---|---:|---:|---|
| 0 (easy) | `RandomInt < 5` | ≈ 0.0076 % | очень медленно (часы) |
| 1 (normal) | `RandomInt < 12` | ≈ 0.018 % | часы |
| 2+ (hard / very hard / impossible) | `RandomInt < 50` | ≈ 0.076 % | минуты (4-10× быстрее normal) |

`_misc_RandomInt = floor(random × 32768)`, поэтому фактический
шанс — `threshold / 32768`. Переход в смерть происходит на
`Nothing`-тике (см. [`internals/engine/ticks_and_subticks.md`](../../../../internals/engine/ticks_and_subticks.md)).

Ориентир по реальной игре:
- Через 30–60 g-сек после `bfamine = True` начинают умирать первые
  крестьяне.
- За 3–5 минут голода на hard игрок теряет ~50 % крестьян и большую
  часть пехоты.
- Если успеешь восстановить food (натаскать с поля, продать gold
  на рынке) — флаг гаснет, гибель прекращается.

### 2.3. Расход food: формула upkeep

Каждый юнит без `bnohungry = True` накапливает у игрока
`gPlayer.counter.resconsume[food]` через инкремент при создании [^5]:

```
per_unit_resconsume_food = consume.food          # из case-ветки в unit.script
                         + gc_obj_foodperunit    # = 30, если !bnohungry и !bbuilding
```

Расход food за игровую секунду (`player.script:_player_ProcessResourceConsume`):

```
food_per_g_sec = sum_of_resconsume_food × gc_time_to_frames / 20000
               = sum × 32 / 20000  =  sum × 0.0016
```

**Sanity-check (verified empirically 2026-04-29):** 18 австрийских
крестьян (`consume.food = 32`, `bnohungry = False`) простаивают 2
игровые минуты:

```
sum = 18 × (32 + 30) = 1116
food / g-sec = 1116 × 32 / 20000 ≈ 1.786
за 120 g-сек ≈ 214 food   ✓
```

Расход food / g-сек на одного юнита (для `bnohungry = False`):

| Юнит | `consume.food` | + `gc_obj_foodperunit` | итого | food / g-сек |
|---|---:|---:|---:|---:|
| peasant (aus / pol / spa / eng / ukr / sco) | 32 | +30 | 62 | 0.0992 |
| peasant `peatur` / `peaalg` | 28 | +30 | 58 | 0.0928 |
| peasant `pearus` | 26 | +30 | 56 | 0.0896 |
| infantry без явного `consume.food` | 0 | +30 | 30 | 0.0480 |

### 2.3. Связь с pop cap

Если игрок упал ниже `farmused` лимита (см.
[`reference/01_economy.md`](../../../reference/01_economy.md)) — это
**не** запускает `bfamine`. Голод срабатывает только при `food = 0`.
То есть «нет домов» не убивает популяцию автоматически; убивает
только реальный дефицит еды.

## 3. Что происходит при бунте

`brebellion = True` действует **только** на наёмников
(`bmercenary = True`). Логика в `lib/unit.script` [^4]: каждый
`Nothing`-тик (~0.625 g-сек) каждый наёмник делает бросок
`_misc_RandomInt < threshold`, где `_misc_RandomInt = floor(random × 32768)`:

| Difficulty | Threshold | Шанс перехода за тик |
|---|---:|---:|
| 0 (easy) | 100 | 100 / 32768 ≈ **0.305 %** |
| 1 (normal) | 200 | 200 / 32768 ≈ **0.610 %** |
| ≥ 2 (hard / very hard / impossible) | **6000** | 6000 / 32768 ≈ **18.31 %** |

На hard ожидаемое время до перехода одного наёмника составляет
`0.625 / 0.1831 × 0.5 ≈ 1.7 g-сек`. **Армия из 50 наёмников
разбегается почти полностью за 5–10 g-сек.** На easy и normal
бунт практически декоративен.

При переходе наёмник попадает в **виртуального игрока-наёмника**
(`gc_player_mercenaryind = MaxPlayerCount − 1`), автоматически
враждебного всем настоящим игрокам. То есть бывший союзник
становится агрессивным NPC-юнитом, а не нейтралом.

Базовое правило: «не запускай дипцентр, пока не уверен что осилишь
золотой upkeep».

Подробности и контр-меры — в
[`../systems/mercenaries_diplomacy.md` §3-4](../../systems/mercenaries_diplomacy.md).

### 3.1. Кто иммунен к бунту

| Тип | Бунтует? |
|---|---|
| Обычные юниты | Нет (бунт срабатывает только при `bmercenary = True`). |
| Наёмники из дипцентра | Да. |
| Здания | Нет. |

### 3.2. Score-бонус противнику

Когда наёмник погибает в бунте от удара противника, противник
получает **× 3** очков, не × 2 [^1]. Это намеренная награда:
«поймал момент слабости — больше очков». На практике это редко
важно, но в близкой партии по очкам может повлиять на победителя.

## 4. Защита от голода и бунта

### 4.1. От голода

1. **Ставь склады возле полей** — еда поступает быстрее.
2. **Не собирай слишком много пехоты** в начале — `consume.food`
   пехоты выше, чем у крестьян (типично 2–4 в тик против 1).
3. **Меньше потребляющих юнитов**, если знаешь что food будет
   сжимать. Распускай лишних рекрутов.
4. **Резерв food**, особенно перед атакой (когда крестьяне будут
   убиты) — иначе двойной удар: убитые крестьяне + начавшийся голод.

### 4.2. От бунта

1. **Шахты gold с апгрейдом** — резко поднимают income, окупают
   upkeep наёмников.
2. **Дипцентр строй после академии и пары gold-шахт**, не раньше.
3. **Не сваливай в одном месте больше наёмников, чем `income gold`
   способен прокормить**.
4. **Рынок обмен** — продай food/wood за gold, если резервы
   gold пошли в красную зону.
5. **Атака противника** — иногда сам бунт сжигает наёмничью армию
   быстрее, чем противник её разгромит. Если уж пошёл — атакуй
   что-то ценное, чтобы хотя бы что-то получить за гибель отряда.

## 5. Связь с другими флагами

| Флаг | Описание | Файл |
|---|---|---|
| `farmused = 0` | У игрока кончилась еда (через `pop cap`); приводит к **defeat** (см. [`../systems/victory_conditions.md`](../../systems/victory_conditions.md)). |
| `bfamine` | Не приводит к defeat сама по себе; убивает юниты. |
| `brebellion` | Не приводит к defeat; убивает только наёмников. |
| `bleave` | Игрок сдался (через UI «leave»). Defeat немедленно. |

Замечание: `farmused = 0` (победный триггер) и `bfamine` (голод)
**разные вещи**. `farmused = 0` означает «у тебя нет еды
вообще», что приводит к поражению. `bfamine` означает «у тебя
food = 0, и есть жители которым нужно есть», что приводит к
постепенной гибели.

## 6. Открытые эмпирические вопросы

1. **Точная формула вероятности гибели от голода.** Из кода
   `_unit_DoTickFamine` или подобной функции пока не вычитан
   фактический коэффициент. Замерить через серию: 100 крестьян,
   `food = 0` на 60 g-сек, посчитать сколько умерло — вывести
   вероятность за тик.
2. **Кто умирает первым: крестьяне или пехота?** Гипотеза: оба
   проверяются параллельно с равной вероятностью; крестьян просто
   обычно больше. Подтвердить замером в равном составе.
3. **Что считается тиком потребления для бунта?** В скрипте упоминается
   `Nothing-tick`, но что это в g-секундах — не определено. Замерить
   разницу между easy (`5%`) и hard (`18.3%`) → темп
   дезертирства.
