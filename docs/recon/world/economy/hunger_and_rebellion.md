# Голод и бунт наёмников

[← Как устроена игра](../../README.md)

Разбор условий, при которых игра включает технические признаки
`bfamine` (голод) и `brebellion` (бунт), что именно при этом
происходит, кто умирает первым, как защититься. Все ссылки на код —
в [Источниках](#источники) в конце документа.

## Коротко о главном

- **Голод** (`bfamine = True`) включается, когда у игрока
  заканчивается Еда (`food = 0`) **и** на следующем такте потребления
  возникает недостача. Снимается, как только еда снова появляется
  (`food > 0`) или прекращается её потребление (`consume.food <= 0`).
- **Бунт** (`brebellion = True`) включается, когда у игрока
  заканчивается золото (`gold = 0`) и его расход превышает доход
  (`consume[gold] > income[gold]`). Снимается, как только запас
  достигает двух единиц (`gold >= 2`) или расход прекращается
  (`consume[gold] <= 0`).
- Голод убивает обычных юнитов, у которых `bnohungry = False`
  (крестьяне, пехота). Здания, наёмники, ландскнехты не трогаются.
- Бунт уничтожает **только наёмников** (`bmercenary = True`) — со
  скоростью ≈ 18,3 % за такт на высокой и более высокой сложности. См.
  [раздел 3 статьи о наёмниках](../../systems/mercenaries_diplomacy.md).
- Очки за уничтожение мятежного наёмника считаются с множителем
  `× 3` (не `× 2`), что делает рейды по голодающему противнику
  сильнее влияет на счёт [^1].

## 1. Где и когда включается состояние

Логика в `lib/player.script` — процедура потребления ресурсов,
вызывается каждый игровой такт [^2]. Для каждого ресурса:

- Если у игрока есть достаточная сумма (`res[i] >= value`) — ресурс
  списывается, признак (`bfamine` или `brebellion`) сбрасывается в
  `False`.
- Если суммы не хватает, списывается остаток. Для еды (`food`) сразу
  устанавливается `bfamine := True`. Для золота (`gold`) действует дополнительная
  проверка: `brebellion` поднимается только если
  `consume[gold] > income[gold]`.

То есть для **золота** есть защита от частичной оплаты: если
шахты окупают потребление наёмников, бунт не вспыхнёт даже при
`gold = 0`. Для **еды** такой защиты нет: голод включается сразу,
как только запас равен нулю и есть потребляющие её жители.

После расчёта в самом конце процедуры состояние снимается автоматически: если
`brebellion = True`, но условие отпало (есть хотя бы две единицы
золота или его потребление обнулилось), флаг гасится. Аналогично
`bfamine` снимается, когда Еда снова появляется или её потребление
становится нулевым [^2].

То есть **на одном и том же такте** состояние может включиться и сразу
выключиться — например, если ровно в этот же такт игрок продал на
рынке еду или принял караван. В интерфейсе это даст одиночное мигание
красным.

### 1.1. Период проверки

Такт потребления ресурсов — `_player_DoTickResources` или подобный,
вызывается раз в **`_misc_GetTickRes()` секунды**, обычно примерно раз
в игровую секунду (см. [статью об игровых тактах](../../../../internals/engine/ticks_and_subticks.md)).
То есть состояние проверяется примерно 14 раз в реальную секунду на
скорости «Высокая».

## 2. Что происходит при голоде

`bfamine = True` запускает побочный механизм в
`lib/unit.script` — каждый такт все юниты проверяются на признак
«могут умереть от голода». Условия гибели:

| Условие | Результат |
|---|---|
| `bfamine = True` для игрока | Условие срабатывания. |
| `bnohungry = True` у юнита | Иммунитет (никогда не умрёт от голода). |
| `consume.food = 0` у юнита | Иммунитет (он еду не ест → его не за что наказать). |

Для подходящего юнита на каждом такте выполняется проверка генератора
случайных чисел
(см. ниже §2.2) `hp := 0`, юнит умирает мгновенно.

### 2.1. Кто иммунен (`bnohungry = True`)

| Тип | `bnohungry` |
|---|---|
| Все здания | `True` |
| Наёмники (`bmercenary = True`) | `True` |
| Ландскнехты, отдельные элитные юниты | зависит, см. `data.json` |
| Крестьяне | `False` |
| Обычная пехота, кавалерия | `False` |

Точное значение `bnohungry` для каждого юнита — в
[`../../../../data.json`](../../../../data.json), поле `bnohungry`.

### 2.2. Вероятность гибели от голода

Точная формула — проверка генератора случайных чисел с порогом,
зависящим от сложности игрока [^3]:

| Сложность | Технический порог | Шанс смерти за такт | Ожидаемое время до смерти одного юнита |
|---|---:|---:|---|
| 0 («Легко») | `RandomInt < 5` | ≈ 0,0076 % | очень медленно (часы) |
| 1 («Нормально») | `RandomInt < 12` | ≈ 0,018 % | часы |
| 2+ («Трудно», «Очень трудно», «Невозможно») | `RandomInt < 50` | ≈ 0,076 % | минуты (в 4–10 раз быстрее обычной сложности) |

`_misc_RandomInt = floor(random × 32768)`, поэтому фактический
шанс — `threshold / 32768`. Переход в смерть происходит на
такте состояния `Nothing` (см. [статью об игровых тактах](../../../../internals/engine/ticks_and_subticks.md)).

Ориентир по реальной игре:
- Через 30–60 игровых секунд после `bfamine = True` начинают умирать первые
  крестьяне.
- За 3–5 минут голода на высокой сложности игрок теряет около 50 % крестьян и большую
  часть пехоты.
- Если успеть восстановить запас еды (принести её с поля, продать золото
  на рынке) — флаг гаснет, гибель прекращается.

### 2.3. Расход еды

Каждый юнит без `bnohungry = True` накапливает у игрока
`gPlayer.counter.resconsume[food]` через инкремент при создании [^5]:

```
per_unit_resconsume_food = consume.food          # из case-ветки в unit.script
                         + gc_obj_foodperunit    # = 30, если !bnohungry и !bbuilding
```

Расход еды за игровую секунду (`player.script:_player_ProcessResourceConsume`):

```
food_per_g_sec = sum_of_resconsume_food × gc_time_to_frames / 20000
               = sum × 32 / 20000  =  sum × 0.0016
```

**Проверка измерением от 29 апреля 2026 года:** 18 австрийских
крестьян (`consume.food = 32`, `bnohungry = False`) простаивают 2
игровые минуты:

```
sum = 18 × (32 + 30) = 1116
food / g-sec = 1116 × 32 / 20000 ≈ 1.786
за 120 g-сек ≈ 214 food   ✓
```

Расход еды в игровую секунду на одного юнита (для `bnohungry = False`):

| Каноническое название | `consume.food` | + `gc_obj_foodperunit` | Итого | Еды в игровую секунду |
|---|---:|---:|---:|---:|
| Крестьянин Австрии, Польши, Испании, Англии, Украины или Шотландии | 32 | +30 | 62 | 0,0992 |
| Крестьянин Турции или Алжира (`peatur`, `peaalg`) | 28 | +30 | 58 | 0,0928 |
| Крепостной России (`pearus`) | 26 | +30 | 56 | 0,0896 |
| Пехотинец без явно заданного `consume.food` | 0 | +30 | 30 | 0,0480 |

### 2.4. Связь с пределом населения

Если игрок упал ниже предела населения `farmused` (см.
[справочнике по экономике](../../../reference/01_economy/README.md)) — это
**не** запускает `bfamine`. Голод срабатывает только при нулевом
запасе еды (`food = 0`).
То есть «нет домов» не убивает популяцию автоматически; убивает
только реальный дефицит еды.

## 3. Что происходит при бунте

`brebellion = True` действует **только** на наёмников
(`bmercenary = True`). Логика в `lib/unit.script` [^4]: каждый
на техническом тике состояния `Nothing` (примерно раз в 0,625 игровой секунды)
каждый наёмник проходит проверку
`_misc_RandomInt < threshold`, где `_misc_RandomInt = floor(random × 32768)`:

| Сложность | Технический порог | Шанс перехода за тик |
|---|---:|---:|
| 0 («Легко») | 100 | 100 / 32768 ≈ **0,305 %** |
| 1 («Нормально») | 200 | 200 / 32768 ≈ **0,610 %** |
| ≥ 2 («Трудно», «Очень трудно», «Невозможно») | **6000** | 6000 / 32768 ≈ **18,31 %** |

На высокой сложности ожидаемое время до перехода одного наёмника составляет
`0.625 / 0.1831 × 0.5 ≈ 1.7 g-сек`. **Армия из 50 наёмников
разбегается почти полностью за 5–10 игровых секунд.** На лёгкой и обычной
бунт практически декоративен.

При переходе наёмник попадает в **виртуального игрока-наёмника**
(`gc_player_mercenaryind = MaxPlayerCount − 1`), автоматически
враждебного всем настоящим игрокам. То есть бывший союзник
становится агрессивным юнитом под управлением игры, а не нейтральным.

Базовое правило: «не строй Дипломатический центр, пока не уверен, что осилишь
регулярный расход золота».

Подробности и способы защиты — в
[разделах 3–4 статьи о наёмниках](../../systems/mercenaries_diplomacy.md).

### 3.1. Кто иммунен к бунту

| Тип | Бунтует? |
|---|---|
| Обычные юниты | Нет (бунт срабатывает только при `bmercenary = True`). |
| Наёмники из дипцентра | Да. |
| Здания | Нет. |

### 3.2. Дополнительные очки противнику

Когда наёмник погибает в бунте от удара противника, противник
получает **× 3** очков, не × 2 [^1]. Это намеренная награда:
«поймал момент слабости — больше очков». На практике это редко
важно, но в близкой партии по очкам может повлиять на победителя.

## 4. Защита от голода и бунта

### 4.1. От голода

1. **Ставь склады возле полей** — еда поступает быстрее.
2. **Не набирай слишком много пехоты** в начале — `consume.food`
   пехоты выше, чем у крестьян (типично 2–4 в тик против 1).
3. **Сокращай число потребляющих юнитов**, если запас еды будет
   уменьшаться. Распускай лишних рекрутов.
4. **Держи запас еды**, особенно перед атакой, когда крестьяне могут быть
   убиты) — иначе двойной удар: убитые крестьяне + начавшийся голод.

### 4.2. От бунта

1. **Улучшай золотые шахты** — это резко повышает доход и покрывает
   содержание наёмников.
2. **Строй Дипломатический центр после Академии и пары золотых шахт**, не раньше.
3. **Не нанимай больше наёмников, чем позволяет доход золота
   (`income[gold]`)**.
4. **Используй Рынок** — продай еду или дерево за золото, если его
   запас стал опасно мал.
5. **Атака противника** — иногда сам бунт сжигает наёмничью армию
   быстрее, чем противник её разгромит. Если уж пошёл — атакуй
   что-то ценное, чтобы хотя бы что-то получить за гибель отряда.

## 5. Связь с другими состояниями

| Технический признак | Описание | Файл |
|---|---|---|
| `farmused = 0` | Исчерпан предел населения; приводит к **поражению** (см. [условия победы](../../systems/victory_conditions.md)). |
| `bfamine` | Сам по себе не приводит к поражению; убивает юнитов. |
| `brebellion` | Не приводит к поражению; затрагивает только наёмников. |
| `bleave` | Игрок сдался через интерфейс. Поражение наступает немедленно. |

Замечание: `farmused = 0` (победный триггер) и `bfamine` (голод)
**разные вещи**. `farmused = 0` означает «у тебя нет еды
вообще», что приводит к поражению. `bfamine` означает «еда
закончилась (`food = 0`), и есть жители, которым нужно есть», что приводит к
постепенной гибели.

## 6. Открытые эмпирические вопросы

1. **Точная формула вероятности гибели от голода.** Из кода
   `_unit_DoTickFamine` или подобной функции пока не вычитан
   фактический коэффициент. Замерить через серию: 100 крестьян,
   `food = 0` на 60 игровых секунд, посчитать сколько умерло — вывести
   вероятность за такт.
2. **Кто умирает первым: крестьяне или пехота?** В коде нет
   приоритета по типу юнита: `unit.inc/nothing.inc:482` проходит по
   всем юнитам игрока без `bnohungry` с одной и той же проверкой
   генератора случайных чисел
   `_misc_RandomInt < threshold`. Крестьяне умирают «первыми»
   только потому, что их обычно больше, и за тот же цикл проверки
   статистически больше попадает в смертельный диапазон. Можно
   уточнить замером в равном составе (например, 50 крестьян + 50
   пикинёров): пропорции должны совпадать.
3. **Что считается тактом потребления для бунта?** В скрипте упоминается
   такт состояния `Nothing`, но его длительность в игровых секундах не
   определена. Замерить разницу между низкой (`5 %`) и высокой
   (`18,3 %`) сложностью → темп
   дезертирства.
