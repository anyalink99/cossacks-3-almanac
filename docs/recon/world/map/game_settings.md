# Как настройки матча влияют на игру

[← Как устроена игра](../../README.md)

Здесь разобрано, как движок Cossacks 3 применяет выбранные перед матчем
настройки. Это ручное исследование игровых скриптов: сначала даётся понятное
игровое название, а точное имя поля или функции приводится рядом в `code`.

Числовые значения и названия из игры собраны отдельно:

- **[`docs/reports/map/lobby_settings.md`](../../../reports/map/lobby_settings.md)** —
  готовый справочник всех настроек (названия из локализации, числовые значения,
  значения по умолчанию).
- **[`derived/game_settings.json`](../../../../derived/game_settings.json)** — то же
  самое в машинно-читаемом виде, для редактора и инструментов.

Здесь объясняется то, чего не видно в таблице: какие функции скриптов читают
эти значения, какие флаги выставляют, какие игровые механики при этом
включаются. Все ссылки на код и блоки Pascal собраны в разделе
[Источники](#источники) в конце документа.

## 1. Как хранятся настройки матча

Структура настроек (`TMapSettings`) разделена на две части [^1]:

- **генерация карты** (`gen`) — рельеф, размер, ресурсы и сезон;
- **правила партии** (`additional`) — время мира, лимит населения, скорость и
  помощник.

Настройки сохраняются в файл сохранения функцией `_misc_SaveLanRoomData` [^2].

В части генерации (`TMapSettingsGen`) находятся ключи генератора случайных
чисел (`randkey0` для расстановки, `randkey1` для рельефа), размер карты
(`mapsize`), тип местности (`terraintype`), рельеф (`relieftype`), стартовые
ресурсы (`resourcestart`), богатство месторождений (`resourcemines`) и сезон
(`season`) [^3].

В части правил (`TMapSettingsAdditional`) находятся дополнительные условия
(`activeoption`), стартовая армия (`startingunits`), воздушный шар (`balloon`),
артиллерия (`cannons`), время мира (`peacetime`), XVIII век (`century18`),
захват (`capture`), рынок и дипломатический центр (`marketdip`), команды
(`teams`), автосохранение (`autosave`), лимит населения (`limit`), скорость
игры (`gamespeed`) и помощник (`adviserassistant`) [^4].

Числовые значения и человеческие названия — в
[`reports/map/lobby_settings.md`](../../../reports/map/lobby_settings.md). Здесь — что
именно читает движок.

## 2. Настройки генерации карты

| Настройка | Поле | Что делает |
|---|---|---|
| Размер карты | `mapsize` [^5] | Задаёт ширину и высоту квадратной карты в тайлах. Влияет также на плотность размещения объектов (`prob*`) [^6]. |
| Тип местности | `terraintype` [^7] | Выбирает базовую маску из `data/gen/terrainmasks/`. Варианты «Полуострова», «Острова» и «Континенты» создают морские воды, доступные только кораблям и порту (`por`). |
| Рельеф | `relieftype` [^8] | Задаёт плотность гор и холмов (`mnt`, `hgh`). При варианте «Высокогорье» (`relieftype = 3`) остаётся меньше ровных площадей для ферм и складов. |
| Стартовые ресурсы | `resourcestart` [^9] | Выдаёт каждому игроку выбранное количество каждого из шести ресурсов: 1000, 4000, 5000 или 1 000 000. |
| Месторождения | `resourcemines` [^10] | Передаётся в плотность шахт (`minesdensity`). Например, на маленькой богатой карте движок делает до трёх раундов по трём видам месторождений. Подробнее — [в разборе генерации карты](map_generation_pipeline.md#8-как-размещаются-месторождения). |
| Сезон | `season` [^11] | Для пустыни включает флаг `bDesert` и заменяет обычные наборы объектов (`forests_pinefir_*`) пустынными (`desert_forests_*`). Остальные сезоны в основном меняют текстуры. |
| Ключи генерации | `randkey0`, `randkey1` [^12] | `randkey1` используется при построении рельефа (`SetRandomKey`), а `randkey0` — при расстановке объектов. Вместе с базовой маской (`inputbitmap`) они однозначно задают карту. Подробнее — [что определяет уникальную карту](map_generation_pipeline.md#12-seed-space). |

> **Тип леса на «Суше».** Игрок выбирает тип леса (`foreststype`) в комнате
> матча, но для карты «Суша» (`terraintype = 0`) движок сразу заменяет его на
> `0` [^13]. На остальных типах местности выбор сохраняется.

## 3. Дополнительные правила партии

<a id="31-startingunits--стартовая-армия"></a>
### 3.1 Стартовая армия (`startingunits`)

Конкретный набор юнитов / зданий для каждого варианта читается из
`data/game/var/startingsettings.cfg`. Поля: `addresources` (доп. ресурсы),
`countries` (легенда расстановки: `P` = крестьянин, `X` = пехотинец, `B` =
барабанщик, `O` = офицер, `Q`/`W` = здания для сценариев и т. д.).

> **Базовые 18 крестьян появляются всегда.** Независимо от выбора движок
> вызывает `CreateStartPointPeasants` и расставляет **18 крестьян** в сетке
> 6×3 вокруг стартовой точки с радиусом 0.75 тайла [^14]. Даже на «По
> умолчанию» у игрока сразу 18 крестьян.

<a id="peacetime--как-устроен-мир"></a>
### 3.2 Время мира (`peacetime`)

Функция `_misc_GetPeaceTime` декодирует индекс в игровые минуты и умножает на
60, чтобы получить игровые секунды [^15]:

| Значение (`ind`) | Игровые минуты |
|---:|---:|
| 0 | 0 (без времени мира) |
| 1 | 10 |
| 2 | 20 |
| 3 | 30 |
| 4 | 45 |
| 5 | 60 |
| 6 | 90 |
| 7 | 120 |
| 8 | 180 |
| 9 | 240 |
| 11 | 15 |

Минуты — **игровые**: на высокой скорости (`gamespeed = 2`) одна игровая минута
≈ 42.9 реальных секунд, и 10-минутный мир длится ≈ 7 реальных минут.

При генерации карты [^16]:

- `gbool_peacemode := (peacetime <> 0)` — флаг включается, если выбран любой
  ненулевой пресет.
- `gfloat_peacetime := _misc_GetPeaceTime(ind)` — конкретное значение в
  игровых секундах.
- `SetupBorderObjects` создаёт визуальные «границы» вокруг каждого игрока.

Пока `gbool_peacemode = True`:

- **Поиск врагов запрещён.** В `_unit_SearchEnemy*` проверяется `bpeacetime`
  — если `True`, ни один юнит не находит врагов и не атакует [^17].
- **Сетка владения территорией.** `_misc_IsCorrectScanCellOwner` возвращает
  `True` только для ничейных и собственных ячеек — враги не могут зайти на
  твою территорию [^18].
- **Захват зданий запрещён** на чужой территории.

Каждый служебный такт типа `Nothing` сервер проверяет окончание мира [^19]: если
`gbool_peacemode = True` и `gametime > gfloat_peacetime`, и при этом партия не
реплей и не клиент — флаг сбрасывается, `ptborder`-объекты удаляются, и партия
переходит в военный режим. Решение принимает только ведущая сторона: сервер
в сетевой игре или сама игра в одиночном режиме. В реплеях и у клиентов
состояние приходит через событие синхронизации (`sync-event`).

<a id="33-century18--переход-в-18-век"></a>
### 3.3 Переход в XVIII век (`century18`)

| Значение | Что делает |
|---|---|
| 0 | Обычные правила: улучшение «Переход в XVIII век» (`<nat>cen.1`) доступно после постройки Академии (`aca`), Собора (`tem`) и Артиллерийского депо (`art`). |
| 1 | Улучшение `cen.1` отключено — XVIII век недоступен. |
| 2 | Игрок начинает в XVIII веке — `cen.1` уже изучено. |

Для Украины (`ukr`), Турции (`tur`) и Алжира (`alg`) опция «Сразу» бесполезна:
у этих наций нет улучшения `cen.1` в `country.script`. См.
[`reference/05_upgrades/README.md`](../../../reference/05_upgrades/README.md).

<a id="34-capture--правила-захвата"></a>
### 3.4 Правила захвата (`capture`)

Геометрия захвата (радиусы, кто захватывается, кто нет, башни, стены) — в
[`recon/world/economy/capture_mechanics.md`](../economy/capture_mechanics.md).

Опция `capture` в лобби только включает / отключает классы целей: `1` запрещает
захват крестьян, `2` ещё и Городских центров, `3` оставляет только захват
артиллерией. Сам алгоритм проверки одинаковый.

<a id="35-marketdip--рынок-и-дипцентр"></a>
### 3.5 Рынок и дипломатический центр (`marketdip`)

`value = 4` («Дорогие наёмники») умножает цену найма на
`gc_gameplay_expensivemercskoef = 3`. Подробности про экономику дипцентра — в
[`recon/systems/mercenaries_diplomacy.md`](../../systems/mercenaries_diplomacy.md).

<a id="36-gamespeed--скорость-партии"></a>
### 3.6 Скорость партии (`gamespeed`)

Константы `gc_settings_gamespeed_*` задают число тиков на реальную секунду:
`slow = 7` («Медленно»), `normal = 10` («Нормально»), `fast = 14` («Быстро»);
четвёртое значение `20` для сверхвысокой скорости (`ultra-fast`) в
коде закомментировано [^20]. `gc_time_to_frames = 32` всегда (32 кадра в одной
игровой секунде); меняется только соотношение игрового и реального времени.

| Скорость | Тиков / реальную секунду | Множитель | Реальное время на 1 игровую секунду |
|---:|---:|---:|---:|
| 0 — медленно (`slow`)   | 7  | ×0.7 | 1.43 реальных секунд |
| 1 — нормально (`normal`) | 10 | ×1.0 | 1.00 реальных секунд |
| 2 — быстро (`fast`)   | 14 | ×1.4 | 0.71 реальных секунд |

<a id="37-limit--лимит-населения"></a>
### 3.7 Лимит населения (`limit`)

Это **глобальный потолок поверх** локального лимита по зданиям:

```
pop_cap = cen × 100 + bar × 150 + ba2 × 250 + hou × 25
```

Глобальный потолок (`limit = 1..8` → 500 / 750 / 1000 / 1500 / 2200 / 3000 /
5000 / 8000) никогда не превышается, даже если ферм-бонус позволяет больше.

Интерфейс выводит значение через строку локализации
`randommap.settings.limit.custom = "%value% юнитов"`; число подставляет
`_misc_GetLimitText`.

<a id="38-adviserassistant--помощник"></a>
### 3.8 Помощник (`adviserassistant`)

Контекстные подсказки в углу экрана. На ход игры не влияют.

## 4. Сложность ИИ — `gc_player_difficulty_*`

Перечислены константы `gc_player_difficulty_*` от `-1` до `4` [^21]:

| Значение (`difficulty`) | Строка локализации | Уровень | Множитель скорости |
|---:|---|---|---:|
| -1 | отсутствует | Нет ИИ | — |
| 0  | `difficulty.1` | Лёгкий | 0.30 |
| 1  | `difficulty.1` | Нормальный | 0.50 |
| 2  | `difficulty.2` | Тяжёлый | 0.75 |
| 3  | `difficulty.3` | Очень тяжёлый | 1.00 |
| 4  | `difficulty.4` | Невозможный | 1.25 |

Множитель применяется через `_player_GetDifficultyKoef` к скорости
постройки и найма у ИИ. **Стартовых ресурсов ИИ не получает** ни на какой
сложности. Подробнее — [`recon/systems/ai_behavior.md`](../../systems/ai_behavior.md).

См. также [`recon/systems/mercenaries_diplomacy.md`](../../systems/mercenaries_diplomacy.md) §3 — на
на тяжёлом уровне и выше при `brebellion = True` шанс перехода наёмников
≈ 18.31% за такт
(значительно).

## 5. Глобальные константы партии

Это не лобби-опции, а константы движка, которые определяют форму всех
настроек [^22].

| Константа | Значение | Что значит |
|---|---:|---|
| `gc_MaxPlayerCount` | 12 | Максимум игроков (включая нейтрала и слот наёмников). |
| `gc_MaxObjCount` | 32000 | Жёсткий предел числа юнитов на карте у всех игроков вместе. |
| `gc_time_to_frames` | 32 | Кадров в одной игровой секунде. |
| `gc_buildtime_modifier` | 10 | Дополнительный множитель **только для зданий**: время в игровых секундах = `frames × 10 / 32`. Для юнитов множителя нет. |
| `gc_resource_hitsneeded_food` | 22 | Ударов мотыгой до сдачи еды. |
| `gc_resource_hitsneeded_wood` | 14 | Ударов топором до сдачи дерева. |
| `gc_resource_hitsneeded_stone` | 20 | Ударов киркой до сдачи камня. |
| `gc_obj_resource_portion_food` | 45 | Еды за рейс при `eff = 100`. |
| `gc_obj_resource_portion_wood` | 28 | Дерева за рейс при `eff = 100`. |
| `gc_obj_resource_portion_stone` | 40 | Камня за рейс при `eff = 100`. |
| `gc_obj_speed_peasant` | 40 | Заявленная скорость крестьянина — но в скрипте присвоение закомментировано [^23] (см. [`recon/world/economy/peasant_extraction.md`](../economy/peasant_extraction.md) §9). |

## 6. Победа и поражение

См. отдельный документ — [`recon/systems/victory_conditions.md`](../../systems/victory_conditions.md).
Кратко: победа = «осталась только одна команда»; `farmused = 0` ⇒ поражение,
но `farmused` не падает в 0 пока есть хоть один крестьянин **или** Городской
центр. Победы через чудо в Cossacks 3 нет, очки (`score`) нужны только для
статистики.
