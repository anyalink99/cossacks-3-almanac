# Обзор и туман войны

[← Как устроена игра](../../README.md)

Как считается радиус обзора каждого юнита, как
устроен туман войны, в каких ситуациях он отключён, как работает
общий обзор у союзников. Все ссылки на код — в
[Источниках](#источники).

## Коротко

- **Радиус обзора** одного юнита — `20 + 4 × vision`, где `vision`
  — поле из `data.json` (значения 0..8) [^1].
- Обзор зависит от состояния: только живые (`bdead = False`) и
  достроенные (`bbuilt = True`) объекты дают обзор; невидимые
  (`GetGameObjectVisible = False`) — нет.
- Туман войны включается / выключается через нативный
  `SetFOWEnable(b)`; **отключён**, если у игрока есть воздушный
  шар (`bballoon`), выбрана настройка лобби «с воздушным шаром»
  (`balloon = with`) или
  партия закончилась победой/поражением [^2].
- Союзный обзор передаётся автоматически: каждый игрок-наблюдатель
  добавляется в список тумана войны через `AddFOWPlayers` для всех союзников по
  команде [^2].
- Прямую видимость рассчитывает движок, а не скрипт. Скрипт только
  поставляет функцию `_unit_GetVision(handle) → radius` через
  `SetFOWDovFunc`; остальная реализация скрыта в нативном коде.
- Снаряды-разведчики (`fogreveal`-свойство) на короткое время
  открывают зону вокруг точки приземления — например, ракеты
  воздушного шара, лётный фонарь.

---

## 1. Радиус обзора каждого юнита

Источник — процедура `_unit_GetVision`, которую движок вызывает
для каждого видимого объекта на карте [^1]. Внутри — две константы
(`cBaseVal = 20`, `cModVal = 4`) и одна формула: если объект
физически отрисовывается, не мёртв и достроен,
`res := floor(cBaseVal + cModVal × objprop.vision)`; иначе — `res := 0`.

Формула: **`radius = 20 + 4 × vision`**, в условных единицах
движка (≈ пикселях / `pixels_to_tile`).

| Обзор (`vision`, поле `data.json`) | Кто |
|---:|---|
| `0` | Большинство простых пехотинцев и крестьян. |
| `2` | Кавалерия, конная артиллерия. |
| `3` | Стрелковая пехота 18 в. (мушкетёры, гренадёры). |

Числовые примеры:

| Юнит | Значение `vision` | Радиус, тайлов |
|---|---:|---:|
| Крестьянин | 0 | 20 |
| Пикинёр 17 в. | 0 | 20 |
| Драгун | 2 | 28 |
| Мушкетёр 18 в. | 3 | 32 |
| Башня | 3 | 32 |

**Единица — тайлы напрямую.** В отличие от радиусов оружия (где
число хранится в пикселях и делится на `gc_pixels_to_tile = 53.3333`),
радиус тумана войны возвращается уже в тайлах. То есть `vision = 0` даёт
20 тайлов обзора, а `vision = 3` — 32 тайла. Это подтверждается
визуально и согласуется с тем, что Башня (`vision = 3`, радиус 32)
открывает заметно большую зону, чем её собственный
радиус поиска цели `searchradius = 26.25` тайла (см.
[`towers.md` §2.2](towers.md)).

## 2. Условия выдачи обзора

Объект даёт обзор только если все условия истинны:

1. `GetGameObjectVisibleByHandle(handle) = True` — игровой объект
   физически отрисовывается.
2. `not bdead` — не мертвый.
3. `bbuilt = True` — здание достроено (для зданий это критично:
   стройка не светит карту).

Если любое условие нарушено — `res := 0`. То есть стройка башни
**не показывает округу** до завершения. Но как только башня
достроена — её значение `vision = 3` раскрывает пространство радиусом
32 тайла.

## 3. Снаряды-разведчики (`fogreveal`)

Особый случай — снаряды с тегом `fogreveal` (свойство
`StringPropertyTag = gc_properties_stringtag_fogreveal`) [^3].
Для них вместо стандартного расчёта возвращается `floor(TProj(pproj).dx)`
— то есть `dx` снаряда (длина траектории / радиус разлёта).
Используется для:

- **Стрельба воздушного шара** — открывает зону вокруг приземления.
- **Сигнальные ракеты / лётные фонари** в кампании.

Эффект временный (пока проектиль существует) и накладывается
поверх обычной карты тумана войны.

## 4. Туман войны: включение и отключение

Точка управления — процедура `_player_UpdateFOW` в
`lib/player.script` [^2]. Она исполняет четыре шага:

1. Считает базовое значение `bFOW := True`, затем сбрасывает в
   `False`, если у игрока есть воздушный шар, опция лобби
   «с воздушным шаром» (`balloon = with`) активна или партия закончилась
   (`victorystate ≠ none`); редактор тоже может выключить туман войны
   через `gbool_editor_fogofwar = False`.
2. Очищает список наблюдателей (`ClearFOWPlayers`).
3. Если `bFOW = True`, добавляет самого игрока в список общего обзора через
   `AddFOWPlayers(GetPlayerHandleByIndex(plInd))`, затем
   проходит по `gc_MaxPlayerCount` и **добавляет всех союзников
   по команде** (с исключением для нейтральных в кампании).
4. Регистрирует функцию расчёта обзора через
   `SetFOWDovFunc('_unit_GetVision')` и активирует туман через
   `SetFOWEnable(bFOW)`.

### 4.1. Когда туман войны отключён полностью

| Причина | Эффект |
|---|---|
| Игрок построил воздушный шар (`bballoon = True`) | Видит всю карту до конца партии. |
| Настройка лобби «с воздушным шаром» (`balloon = with`) | Все игроки начинают со всеобщим обзором. |
| Игрок выиграл / проиграл (`victorystate ≠ none`) | После окончания игры видна вся карта. |
| Редактор карт отключил туман войны (`gbool_editor_fogofwar = False`) | Только в редакторе. |

### 4.2. Союзный обзор

Каждый член команды добавляется в общий обзор через `AddFOWPlayers`.
**Союзники по команде автоматически делятся обзором**.
Отдельная кнопка «поделиться обзором» не нужна — это поведение
встроено и неотключаемо.

Исключение в скрипте — для сценариев (`plInd = 0`, главный
игрок-герой): его обзор не делится с **нейтральными**
персонажами (`bneutral = True`), чтобы они не «выдавали» позицию игрока.

## 5. Связь с другими системами

### 5.0. Звук

Звуковая система **не привязана к туману войны**. Источники звука
(`SndGetOrCreateSound`) проверяют только расстояние до точки прослушивания
(камеры или объекта). Это значит: скрытый туманом войны вражеский юнит
(ты его не видишь) **слышен**, если он в радиусе слышимости
камеры. Полный разбор — в
[`../../systems/ui_input_and_feedback.md` §5](../../systems/ui_input_and_feedback.md).

### 5.1. Целеуказание

Обзор и целеуказание — **разные** механики:
- Обзор работает с радиусом `20 + 4 × vision` (см. §1).
- Целеуказание (`_unit_SearchEnemy*`) работает с радиусом оружия —
  `weapon.radiusmin`, `weapon.radiusmax`. См.
  [`target_selection.md`](target_selection.md).

То есть юнит может **видеть** дальше, чем **стрелять**. Башня с
`vision = 3` (радиус 32 тайла) видит окрестности, но дальность оружия
`weapon.radiusmax` меньше: она знает, что враг рядом, но ещё не достаёт его.

### 5.2. Поиск пути

Обзор **не влияет** на построение пути. Поиск пути работает по
полной карте (видит препятствия везде, не только в зоне обзора).
Если враг построил ловушку (стену) во время твоего движения, юнит
обойдёт её, даже если ты её не «видишь».

### 5.3. Компьютерный игрок

Компьютерный игрок тоже **видит только через туман войны**. Поэтому рейд по
скрытым тропам в спину работает — если ты не светишь свои отряды,
ИИ не реагирует. Подробности — в
[`../systems/ai_behavior.md`](../../systems/ai_behavior.md).

## 6. Что ещё требует проверки

1. **Точное преобразование `radius` в тайлы.** Формула возвращает
   значение в неясных единицах (вероятно, собственная единица тумана войны
   движка). Нужно замерить: поставить юнит с известным `vision`,
   засечь видимое расстояние линейкой через скриншот.
2. **Скорость обновления тумана войны.** Карта видимости обновляется каждый кадр или
   каждые N мс? Скрипт только устанавливает функцию через
   `SetFOWDovFunc`; обновление — нативное. Нужно замерить через
   быстро движущуюся конницу: на сколько кадров область видимости отстаёт от
   позиции юнита.
3. **Память тумана войны.** Однажды разведанные участки карты остаются
   видимыми (как «серый туман»), но мы не уверены, сохраняются ли
   там объекты. Гипотеза: сохраняется только рельеф, а юниты и
   здания видны только в текущей области обзора. Это нужно измерить.
