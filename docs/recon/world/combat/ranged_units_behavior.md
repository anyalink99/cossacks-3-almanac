# Recon: поведение стрелковых юнитов

Глубокий разбор: режимы атаки стрелков (standground, bartprepare,
RunAway), штраф к дальности при движении, бонус к дальности в
покое, переключение оружия по дистанции, бонус с высокой
позиции. Все ссылки на код — в [Источниках](#источники).

> **Связанные документы:** [`combat_damage_pipeline.md`](combat_damage_pipeline.md) —
> формула урона; [`target_selection.md`](target_selection.md) —
> алгоритм выбора цели; [`unit_commands.md`](unit_commands.md) —
> очередь приказов; [`artillery_specifics.md`](artillery_specifics.md)
> — отдельно про артиллерию.

## TL;DR

- **Standground** — флаг отряда «стоять». В standground стрелок
  сканирует врагов на полную `searchradius` (28-45 тайлов), без —
  только на ~`minsearchdist + 0.375` тайлов (почти ближний бой).
- **Bartprepare** — флаг для артиллерии, башен и портов: при
  получении `attackpoint`-приказа принудительно отключает
  standground и активирует поиск целей вокруг точки.
- **RunAway** — стрелок отступает на 3.5 тайла, если враг вошёл в
  его «мёртвую зону» (`< minsearchdist`). Не работает в standground.
- **Standtime < 0.25 г-сек** — стрелок только что двигался, теряет
  до 3 тайлов эффективной max-range (`uniqrnd × 3`); артиллерия —
  до 1.5 тайла.
- **Idle-state** добавляет `addradius` к дальности (~0.6 тайла).
- **Multi-weapon** юниты автоматически переключают оружие по
  дистанции: пушка → ядро на дальней / картечь на ближней;
  мушкетёр 18 в. → пуля на дальней / штык в упор.
- **High ground**: на холме (Y > 0) стрелок видит дальше:
  `searchdist += goHeight × 2`.

## 1. Standground vs обычный режим

Главный механизм определения видимости цели — это разный
`maxsearchdist` в standground и в обычном режиме [^1].

В **standground** (флаг `bstandground = True` плюс приказ — не
`move`):

```
maxsearchdist = MIN(searchradius, GetMaxAttackRadius)
```

То есть полная дальность оружия (~28-45 тайлов).

В **обычном** режиме (без standground или приказ `move`):

```
maxsearchdist = minsearchdist + 0.375
```

То есть **почти melee** — стрелок обнаруживает врага только когда
тот вплотную подошёл.

### 1.1. Что это значит на практике

| Режим | Что происходит |
|---|---|
| Standground (`hold position`) | Мушкетёр на холме делает 5–10 выстрелов до ближнего боя. |
| Обычный (`move`/`attack`) | Тот же мушкетёр успевает 1–2 выстрела, потом враг подбегает. |
| Приказ движения | Стирает standground: `if (order = move)` блокирует ветку. |

**Оборона = standground обязательно.** Без него стрелковые юниты
выглядят «глухими»: стоят и не реагируют на врага в дальней зоне,
открывают огонь только на 1-2 тайла.

## 2. Bartprepare — режим артиллерии

`bartprepare = True` — флаг для артиллерии, башен (`tow`) и
портов (`port`). Когда такой юнит получает приказ
`attackpoint(trgx, trgz)` (по площади), скрипт принудительно
переключает режимы [^2]:

| Что меняется | Как |
|---|---|
| `bstandground` | принудительно сбрасывается в False |
| `bsearchenemy` | принудительно ставится в True (активный сканер) |
| Получает приказ | `attackpoint` с задержкой `attackdelay`/`attackmaxdelay` |

То есть артиллерия в `attackpoint`-режиме **не стоит на одном
месте**, а активно сканирует зону вокруг цели и обстреливает
любого, кто там окажется.

Без `bartprepare` (мобильная картечница, мушкетёр) команда
`attackpoint` работает как `move(x, z)` — без активного поиска.

См. также [`artillery_specifics.md`](artillery_specifics.md) §3
о приказе `attackpoint` и подготовке выстрела.

## 3. RunAway — отход стрелка из мёртвой зоны

Если у стрелкового юнита (`minsearchdist > 0`) враг вошёл в
**мёртвую зону** (между `0` и `minsearchdist`, то есть слишком
близко для выстрела), и юнит **не в standground** — он отступает
на `gc_unit_runawaydist = 3.5` тайла назад [^3].

### 3.1. Условия запуска

Все три должны быть истинными:

1. Юнит **не** в standground.
2. Враг — в зоне `[0, minsearchdist]`.
3. Стартовое условие (одно из):
   - `standtime = 0` (только что подошёл / завершил выстрел);
   - `standtime > gc_unit_runawaydelay = 1.3` g-сек (стоял
     достаточно долго);
   - **Или** игрок-человек на сложности easy / normal — тогда
     этот гейт пропускается.

### 3.2. Сложность и поведение

| Кто играет | Сложность | Когда отступает |
|---|---|---|
| Игрок-человек | easy / normal | Каждый тик, пока враг в `minsearchdist` (поблажка для новичков). |
| Игрок-человек | hard / very hard / impossible | Только в моменты `standtime = 0` или `> 1.3` (промежуточный «успевает выстрелить»). |
| ИИ | любая | Так же как hard+ для человека — без поблажки. |

### 3.3. Стратегические выводы

- **Удерживаешь холм** — `standground` обязателен, иначе стрелки
  разбегутся при сближении.
- **Отступательная тактика** (отход с обстрелом) — **снять**
  standground; стрелок отбежит на 3.5 t, повернётся, выстрелит,
  снова отбежит.
- **Лёгкая кавалерия** догоняет отходящих стрелков
  (fasthorse=96 против default=32 — в 3 раза быстрее).

## 4. Штраф к дальности при движении (`standtime`)

`standtime` — счётчик «сколько времени юнит стоит на месте». При
движении сбрасывается в 0; при остановке начинает расти.

Если `standtime < 0.25` г-сек, стрелок «трясётся» — теряет в
эффективной max-range [^4]:

```
if (standtime < 0.25) AND (weapon.kind ≠ cannister):
    if (NOT bArtillery):
        radiusmax −= 3 × uniqrnd            # пехота: до −3 тайла
    else:
        radiusmax −= 3 × uniqrnd × 0.5      # артиллерия: до −1.5 тайла
```

Где `gc_obj_maxattackradiusdisp = 3` (из `dmscript.global`), и
`uniqrnd` ∈ `[0, 1)` — фиксированное при спавне число каждого
юнита.

### 4.1. Эффект

- **Стрелок в движении не выстрелит на полную дальность** —
  нужно постоять ~0.25 г-сек. Это объясняет «промахи» по дальним
  целям при подходе.
- **Картечь не штрафуется** (`kind = cannister` — исключение).
- **Артиллерия штрафуется в 2× меньше** — мортира / пушка после
  короткого movement готова стрелять почти на полную.
- В сочетании с RunAway создаёт паттерн **отход → пауза 0.25 →
  выстрел → отход**.

## 5. Бонус к дальности в покое (`addradius`)

Если юнит в idle-состоянии (`statestag` содержит
`gc_statetag_move_idle`), он получает бонус к
`weapon.radiusmax` [^5]:

```
rbonus += weapon[i].addradius     # обычно 32 px = ~0.6 тайла
```

Кому даётся: мушкетёрам, лучникам, пушкам — у всех
`addradius = 32 px = 0.6 t`. Для слабых стен
(`gc_obj_usage_weakwall`) дополнительно **+0.36 тайла** rbonus.

### 5.1. Эффект

Стационарная защита (например, гарнизон на холме в standground)
стреляет на **~0.6 t дальше**, чем тот же отряд в движении. В
сочетании с high-ground (см. §7) и устранением `standtime`-штрафа
получается заметная прибавка к радиусу обороны.

## 6. Переключение оружия по дистанции (multi-weapon)

Многие юниты имеют **несколько слотов оружия** (`weapon[0]`,
`weapon[1]`, ...). Игра автоматически выбирает нужный по
дистанции до цели — каждое оружие имеет
`radiusmin..radiusmax` [^6]. Если враг в близком диапазоне —
выбирается оружие с маленьким `radiusmin`; иначе — дальнее.

Дополнительно учитывается `attmask`: если у цели `mmask`
совпадает с `weapon[i].attmask` (материал брони), это оружие
приоритетнее. Поэтому **огненные стрелы** выбираются для
построек (их `attmask` содержит `gc_obj_material_building`).

### 6.1. Пары multi-weapon юнитов

#### Пушка — ядро против картечи

| Слот | Тип | dmg | pause | range (px) | Когда |
|---|---|---:|---:|---|---|
| `weapon[0]` PPOINTT | cannonball | 1800 | 350 | 550–2160 | дистанция ≥ 550 px (~10.3 t) |
| `weapon[1]` PSMPOINTTPUS | cannister | AoE | 350 | 0–450 | враг ближе 450 px (~8.4 t) |

Пехота, подошедшая на ~8 тайлов к пушке, автоматически попадает
под **картечь** — массовый AoE-урон. Поэтому «навал пехоты на
пушку» = картечь в упор. **Атаковать пушку лучше растянутой
линией**, чтобы под взрывом было не больше 9 юнитов (см.
[`combat_damage_pipeline.md` §5](combat_damage_pipeline.md) о AoE
damage cap).

#### Мушкетёр 18 в. — пуля против штыка

| Слот | Тип | dmg | pause | range (px) | Когда |
|---|---|---:|---:|---|---|
| `weapon[0]` (bayonet) | pike | 5–10 (по нации) | **0** (без cooldown между ударами) | 35–65 (~0.66–1.22 t) | в упор |
| `weapon[1]` SHOTMUSKET | bullet | 16–29 (по нации) | 140–190 | 400–900 (~7.5–16.9 t) | дальше 7.5 t |

Мушкетёр после выстрела **не беспомощен** в ближнем бою — у него
**штык** с pause = 0 (бьёт каждый цикл анимации). Атаковать
перезаряжающихся мушкетёров кавалерией = получить штыковой бой.

Прокачки штыка идут отдельно от прокачек пули
(`bla.musketeer18.1.X` качает урон bullet, штык остаётся
базовый).

#### Лучник — обычная стрела против огненной

| Слот | Тип | dmg | pause | range (px) | dispertion | Особенности |
|---|---|---:|---:|---|---:|---|
| `weapon[0]` STRELA | arrow | 15 | 75 | 400–800 | 175 px | основная стрельба |
| `weapon[1]` OSTRELA | firearrow | **150** | 125 | 400–600 | 200 px | `attmask` = building+wood+woodwall |

Огненные стрелы — **оружие лучников против построек**: урон 150
(в 10 раз больше обычного), но скорострельность хуже на 40 %,
точность на 14 % хуже, и **отрядный бонус к урону не
применяется**. Игра автоматически переключает лучника на
OSTRELA, когда цель — здание / wood / палисад.

#### Прочие

- **Янычар** — пуля + сабля.
- **Стрелец** — пищаль + бердыш.
- **Егерь / драгун** — пуля + сабля.
- **Конные стрелки** (drabant, конный стрелец) — пуля + сабля
  верхом.

Везде логика одна: близко — оружие ближнего боя, далеко —
стрелковое.

## 7. High ground — бонус с возвышенности

Если стрелковый юнит стоит на возвышенности (`Y > 0`), его
**search distance** растёт пропорционально высоте [^7]:

```
searchdist += goHeight × 2     # только для ranged юнитов: minsearchdist > melee_radius
```

`goHeight` — Y-координата юнита в тайлах. Бонус **только к радиусу
обнаружения**, не к самому выстрелу. Но если враг ещё не в зоне
атаки, юнит начинает движение и выстрелит сразу как только цель
войдёт в `radiusmax`. На практике мушкетёры с холма стреляют по
наступающим **раньше** = больше выстрелов до ближнего боя.

Холмы создаются параметром `relief` при генерации карты
(Highlands даёт максимум).

### 7.1. Не работает на

- Юнитов ближнего боя (пикинёр на холме никаких преимуществ не
  получает — он в ближнем бою).
- Юнитов с `searchradius = 0` (мортира, барабанщик и т.д.).

## 8. Открытые эмпирические вопросы

1. **Точная формула RunAway-направления.** В какой стороне
   отступает стрелок? «От врага по прямой» или какой-то более
   умный pathfinding-выбор. Замерить через скриншоты.
2. **Штраф к дальности при `cannister`.** Запись говорит «не
   штрафуется», но `radiusmin` для cannister обычно нулевой —
   нужно проверить, что `radiusmax` действительно не дрогает.
3. **High ground для лучников против AoE.** Если лучник стоит
   на холме и стреляет огненной стрелой по зданию — учитывается
   ли поправка `goHeight × 2` в обнаружении здания, или только
   при поиске юнитов?
